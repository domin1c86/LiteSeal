# 可关闭的单聊阅读回执（T17）

## 行为和隐私边界

- 每个本机账号默认关闭。账号设置中显式启用后，只有聊天窗口在前台、没有遮挡对话框、消息已成功解密且至少有 32 像素进入消息区域时，才记录首次可见并准备回执。已撤回、被本机删除或完整性失败的消息不生成回执。
- 本机未读数仍按原规则处理已加载消息，阅读回执使用另一张“首次可见”表，两者不改变 `ack_v2` 的设备持久化确认。旧版已有的本机已读记录在首次升级时标为已查看，避免启用后补发旧阅读状态。
- 关闭时会删除尚未提交的本机回执任务；已经到达服务端的回执无法撤回。关闭期间首次显示的消息也记录为已查看，重新启用后不会补发。
- 回执事件包含原消息编号、会话、读者、发送者和设备身份；这些元数据对服务端可见，聊天正文和密钥不在回执内。界面只显示“对方已读”，不推断精确阅读时间。当前只覆盖单设备 Windows 单聊。

## 权限和持久化

回执使用独立签名域 `LiteSeal/read-receipt/v1`。服务端验证访问令牌、未撤销设备、读者签名，以及持久消息收据中“原发送者 → 当前读者”的方向；同一读者对同一消息只能提交一次。发送者客户端再次用联系人签名公钥验证事件后才显示回执。服务端按顺序提供增量补收，客户端在 SQLite 保存待发事件和接收游标。

本机新增 `read_receipt_settings`、`local_receipt_seen`、`local_receipt_migrations`、`local_read_receipts` 表；服务端迁移 8 新增 `read_receipt_events`。使用新服务端和新客户端一起验证，旧服务端缺少接口时聊天仍可连接，但界面显示附加状态同步失败。

## 待验收

在专用 PostgreSQL 与两台隔离 Windows 上验证：默认关闭、启用/关闭、滚动到可视区、窗口失焦与对话框遮挡、离线补收、重复提交、撤回/拉黑、权限伪造和旧库升级。当前自动化不能代替这些真实场景；清单 T17 复选框保持未勾选。
