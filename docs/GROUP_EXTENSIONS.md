# 群附件、语音与活动扩展

更新：2026-10-01。在群文字 V1 与 T21 协作之外增加独立扩展版本 1。旧客户端只接收固定的加密文字占位 `[群附件或活动，请升级客户端查看]`；名称、活动详情及附件密钥只在按成员加密的扩展描述中。正常文字协议与 ACK 不变。

## 提交与同步

签名绑定群、成员版本、账号/设备/加入阶段、根消息编号、对象版本与前序哈希、完整受众、逐成员描述摘要及文字根密文摘要。新建根与扩展在同一 PostgreSQL 事务提交，任一步失败均回滚。重试保留原编号、密文和签名；明确版本冲突保留任务，必须取消或重新创建。

扩展使用持久日志及每加入阶段的增量游标，不分配依赖旧客户端 ACK 的新待收队列。客户端验签、解密并原子落库后推进游标。每页最多 100 项，扩展请求/分页最多 512 KiB，单份加密描述最多 8 KiB；每群最多 10,000 条事件和取消记录。文字根继续受原待收配额保护。

## 附件与语音

单文件明文最多 20 MiB，使用随机附件密钥和现有认证加密，密文每块最多 1 MiB。群对象、分块与原受众独立存储；发布时检查完整长度及签名绑定的密文摘要。已发布的编号保留占用证明，过期清理后不能复用编号移植旧授权。

远端下载同时要求有效设备、当前成员资格、未关闭的群和原受众的相同加入阶段，遵守拉黑/拒绝策略。退出、移除或重新加入后拒绝旧远端下载；已验证的本机副本保留，隐藏历史后不能重新显示或导出原内容。

单聊与群共享每账号 512 MiB / 2,000 对象的服务器额度，按统一账号配额锁分配。对象默认 30 天期限，未发布对象默认 24 小时清理，沿用原环境配置。本机共享 256 MiB 缓存，SQLite 写入事务再次校验并发容量；全局及按群清理只删除下载缓存，保护待发任务。逻辑载荷与全库 DB/WAL 文件占用分别显示。

上传不持有群文字网络锁；完整上传后才同步成员并准备消息链。准备前加入阶段改变拒绝发布。已准备任务只能重试原签名，不自动改变受众。服务端取消记录阻止迟到提交；已接受消息不能通过取消任务撤回。

群语音复用 WebM/Opus 录音、试听、丢弃和释放设备组件。页面及 Rust 验证 1–60,000 ms 的时长字段和格式/大小边界；服务器只限制密文大小，不验证加密音频的实际时长。真实麦克风、系统失焦/锁屏与实际播放另做 Windows 验收。

## 活动状态

标题、UTC 开始时间、创建时区、地点与说明加密保存，创建后固定。原受众且仍处于原加入阶段的成员可实名选择参加、不参加或待定；未回应与主动待定分开，改选覆盖原选择。服务端可见实名选择及必要权限元数据。

发起人或当前群主可关闭报名或取消活动。关闭报名保留活动有效状态，取消同时关闭报名，两种操作不可撤销。开始时间不会自动停止报名。离开者原状态保留并标记已离开；重新加入不恢复资格，新成员不取得旧详情。对象版本和前序哈希在群事务锁内检查；相同提交幂等，不同并发修改返回冲突。

附件或活动根只新增一次未读和通用群通知；报名及管理变化只更新状态。静音、前台抑制、锁定与通知去重沿用群实现。

## 备份与验收边界

T22 新导出载荷版本 2，包含已验证的扩展日志、游标与活动状态，排除待发任务。可选群附件仅包含当前身份范围、完整且认证有效的下载缓存；未包含明确不可用。继续读载荷版本 1，旧读取器遇到版本 2 明确失败。

离线档案只读，按原隐藏规则分页显示，不连接服务器或激活设备。附件由 Rust 认证后经主进程选定路径保存/预览；页面不持有密钥、原始路径或通用文件接口。

自动化不替代双 Windows、原生系统交互、完整 24 小时负载或独立审查。实际证据见 `P0_P1_ACCEPTANCE_RECORD.md` 的日期增量。
