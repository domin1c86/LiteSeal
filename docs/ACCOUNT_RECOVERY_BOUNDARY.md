# 账号密码与设备身份恢复边界

## 当前内测行为

- 修改密码必须在原设备的有效会话中提交当前密码。服务端成功修改后撤销该账号全部会话；本机清除令牌，但保留身份密钥、历史和草稿。用户以新密码在同一原设备重新登录。
- 账号密码不是聊天密钥。忘记密码但仍持有设备密钥时，当前版本没有自助重置入口；丢失设备密钥时，改密码、复制 SQLite 或管理员重置密码都不能恢复旧身份和历史。
- 内测阶段不允许自助换机或密钥轮换。确实丢失原设备身份时，由内测维护者建立新账号，并明确告知旧账号的消息与身份不可迁入；不要覆盖旧密钥文件尝试接管。

## 后续恢复能力的前置设计

加密备份 T22 应由用户选定本地文件、独立备份口令和版本校验组成，明确包含数据库、身份密钥及附件范围。恢复须先在隔离目录验证口令、完整性和身份指纹，再讨论是否导入；失败不得覆盖原库。Windows DPAPI 保护的现有密钥文件不能直接作为跨用户或跨机器的便携备份。

可信多设备 T23 应在备份边界明确后设计原设备授权、加入/撤销和密钥分发。服务端必须继续拒绝仅凭账号密码替换原设备或公钥；历史授权和旧消息编辑权限需要单独规则。完成这些设计与故障测试前，D-08 的“账号恢复”保持未实现。

## 验收依据

修改密码需验证错旧密码、并发修改、旧 HTTP/WS/refresh 失效及原设备新密码重登录。将来实现恢复时，至少覆盖错口令、损坏备份、设备已撤销、不同 Windows 用户和恢复中断，记录是否保留同一身份指纹及历史，不得用重新注册冒充恢复。
