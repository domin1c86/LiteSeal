# 群客户端核心（T20）

## 当前范围

`core/src/groups/` 提供 `GroupApi`、`GroupStore` 和 `GroupClient`。成员、收发和存储逻辑放在共享 Rust 核心，密钥由调用方的 Rust 身份所有者保管，不通过渲染进程传入。当前没有 Windows IPC/界面调用这些入口，T20 仍为部分实现，不能据此称桌面群聊可用。

同一账号存储使用一个 `GroupClient`；异步业务锁串行执行网络驱动的成员/收发变更，SQLite 阻塞锁不会跨越网络等待。新群表追加到指定 SQLite 文件，测试只使用内存或独立临时数据库，不读取真实用户历史和密钥文件。

## 身份和成员链

- 本机范围为规范化服务器地址、账号、设备和公开加密/签名身份的带域摘要。地址大小写及根路径末尾斜杠归一化；不接受地址内凭据、查询或片段。更换服务器、设备或公钥不会直接接入旧范围的任务/历史。
- 创建者必须独立核实。自己创建/恢复的群钉住本机身份；接受邀请前，`adopt_invitation` 要求外部提供已核实的群主身份，不能从服务端自签创建事件自动信任群主。后续 Windows 流程须从可信联系人取得并展示这个身份及指纹。
- `GroupState` 由钉住创建者和有序签名事件重放。同步检查分页范围、连续版本、前哈希及签名；重复事件只有完全相同才接纳，分支或回退报错且不覆盖已保存前缀。每页变更在同一本机事务中保存。
- 共有创建、恢复自己创建的群、邀请列表、核实邀请、接受/拒绝、群主改名/移除/关闭及普通成员退出入口。群主/成员权限和双签名加入继续使用共享验证规则。新变更提交失败可在下次签名同步时恢复已接受事件；创建响应丢失时可从远端群列表用本机身份恢复自己的创建记录。

## 加密发件及取消

`queue_text` 先同步当前签名成员版本，封装每个其他成员的一份认证密文及签名信封，并原子保存原批次与自用加密正文。每群只允许一个未完成批次；其他群任务独立。任务保存后，不因网络超时重新生成消息编号、时间、密文或签名。

发件链头只在服务端返回与原群/消息编号及完整收件身份、设备、加入版本匹配的持久收据后更新。收据不足、重复目标或不匹配时保留原任务。下一条使用已接受链头；取消未入库任务不消耗链位置。版本/权限变化导致提交拒绝时，用户需处理原任务后才能重新封装，不自动缩减收件人或改变授权范围。

取消调用服务端原子接口，不会通过再次发送正文确认状态。取消标记和入库竞争在服务端群事务中决定：取消成功后本机任务变为取消，之后可以重新封装新编号；若已经入库，返回原收据，本机按已接受记录处理并提示无法取消。断网或不确定响应保留原批次供重试。已入库消息撤回另属产品功能，当前没有群撤回。

## 收件、ACK 与历史

收件前同步成员链。每份信封校验历史版本和成员哈希、发送签名、本机收件账号/设备/当前加入阶段、序号及前哈希，然后认证解密、检查 UTF-8 和文字上限。在同一本机事务中保存自用加密正文、原签名信封、收件链头和待 ACK 项，成功提交后才调用服务端 ACK。

篡改、错误收件人、链缺口、解密失败及落库故障不 ACK，也不推进链。重复信封验证后只补交待 ACK，不重复显示历史。ACK 请求失败时，本机待确认项保留；重启后下一次轮询继续提交。已签名移除/关闭或新的加入阶段会清理旧阶段的待 ACK 项，历史正文保留，旧阶段信封不能进入新链。

本机正文为身份密钥保护的认证密文，密文内绑定域、本机范围、群编号和消息编号；将另一群的正文密文复制到当前记录会被拒绝。数据库仍不是整库加密：群公开资料、成员链、路由、时间、状态和密文大小可见。保留原身份密钥是读取这些加密正文的前提，当前没有账号/备份恢复产品流程；静态密钥安全边界沿用[小群设计](PRIVATE_GROUP_TRIAL.md)。

历史按本机入库顺序每页最多 100 项，使用本机行游标继续读旧页，新到消息不会挤掉正在读取的旧页。取消的未入库任务不展示为聊天历史。服务端 ACK 表示客户端确认处理完成，与可见已读回执不同。

## 实际验证及下一步

9 项 `core/tests/group_test.rs` 用例通过：加密任务重启、原收据绑定、范围/私钥检查；错误签名/解密/顺序不确认；模拟落库故障使正文/链/ACK 整体回滚；创建信任锚和成员分支；移除与重新加入；模拟 REST 中的重启 ACK、超时原批次重试、未提交取消及已经入库的取消结果；105 条历史分页、密文复制和空任务拒绝；地址和编号输入限制。

本轮完整测试为 12 项 Electron、121 项 Rust 通过，17 项 PostgreSQL 用例未执行；构建、格式、Clippy 及共享核心 `ffi` 编译通过。模拟 REST 只证明客户端处理路径，不代替真实 SQL 和多客户端验收。

下一步将 `GroupClient` 绑定到桌面账号/会话生命周期，更新令牌时保持同一存储范围，提供受锁定门禁保护的业务 IPC，渲染进程只取得公开身份、群资料和解密后的正文。随后接入群列表、创建、明确邀请目标/群主指纹、接受/拒绝、成员管理、文字发送/重试/取消、历史分页和后台补收。真实数据库、隔离多账号及 Windows 交互完成前，T20 不勾选；安装包继续跳过。
