## 2026-10-02 原激活任务的加密持久化与协调

新增 Rust `activation/jobs.rs`。复用 `device_control_tasks` 与既有原生 witness 的覆盖，不新增或改写 SQLite/服务器历史迁移；激活任务使用独立域和账号/根/设备两公钥/任务类型范围。每类最多 128 记录、一个未结束任务，启用与登录分开，最多返回 256 个不含秘密的任务视图；旧授权任务范围与解析保持隔离。打开要求已有独立确认的根，不能以打开任务库代替确认网络响应里的根。

启用原事件、激活原编号/随机申请凭据、用户名、授权阶段/历史目录点、原挑战、原证明字节、取消签名和结果密文先存入认证加密封套。角色、两组私钥/公钥、行修订/类型/终态和封套范围一致才读取；历史目录验证不回退当前 head。密码仅本次请求内存使用，不进入任务；私钥不进表，会话访问/刷新令牌只在 Rust 解封，库内保存设备专属密文。读取挑战只认证密文，不重新生成证明；真正首次证明仍按实际时间检查挑战期限，重试使用已保存的同一字节。

协调器在查询前持久标记 started，原请求/证明保存前不发送；无挑战先查原申请，确实需要口令时由调用者重新提供，不缓存口令。已保存证明直接查询/重试原证明结果，成功回包丢失后不生成新编号或签名。启用原事件先查签名状态，目录冲突保留原事件。取消未发布任务可在本机结束；已开始则先保存原取消签名，继续调用原远端拒绝记录或接受结果，已接受显示 complete 而不是 cancelled。超时、401/403/409/410、无效响应不清原任务或当成成功取消；验证当前签名目录证明原阶段已不在时才结束为 ineligible。

同步 gate/SQLite/native 锁不跨 await，网络使用 Tokio 串行锁。取消增加持久修订，旧回包不能覆盖；锁定清运行时会话并使租约失效，解锁与会话轮换不能恢复旧代次，包括迟到的“需要口令”提示。启用和登录两类待处理范围允许原设备在旧 bearer 无效时，以原启用事件、密码与双密钥证明取得新会话，再查询原启用结果；不阻塞在未知启用任务后，也不凭密码替换设备或公钥。

7 项原生核心短测、14 项实际 HTTP/PostgreSQL 专项及全库 62 项通过，证据见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)。正常 Windows 档案/DPAPI 会话字段、正式会话终态查询/整理、过期冲突的明确再申请流程、IPC/页面和后台尚未接；此切片不替换原身份、不开放第二端普通聊天，不代表双 Windows 或系统验收。正式会话结果仅 Rust 读取，恢复档案不能运行这些任务。

## 2026-10-02 启用与激活取消的持久拒绝记录

增加 PostgreSQL 增量 19，不修改增量 18 或旧迁移。POST `/devices/messaging/cancel` 要求原设备会话及独立取消域的根签名，绑定完整原启用事件摘要；POST `/auth/v3/cancel` 要求当前有效授权阶段的设备签名和原申请凭据，绑定 origin/账号/设备两公钥/阶段/原编号/启用摘要/凭据哈希。发布签名不能代替取消签名，取消无需再次保存或提交账号密码。

两个入口与原启用、begin、proof 共用账号行锁。取消可在原请求尚未到达时写入持久拒绝记录，原编号的迟到启用、begin、challenge 和未接受证明不能越过记录；已存在同范围记录返回原绑定摘要，不将超时、401、403、409 或未知申请当成取消完成。已启用的原事件返回 accepted，保持不可逆；已完成证明返回原挑战及原设备专属会话密文，不新增会话、不声称撤销已激活设备。撤销设备仍通过签名授权日志，原会话已结束、密码已变或原授权阶段不再有效时拒绝重取已接受结果。

每账号的两类取消记录各最多 4,096，达到上限仍可查询同一原记录或已接受结果；不清掉记录后允许旧请求复活。已取消申请不占 8 个活跃挑战名额，但保留原申请及总量上限。申请数、取消记录数均在同一账号锁内检查。固定合成 SQL 大量记录只用于短测额度，不代表长期负载。

Rust SDK 验证取消摘要或精确原 accepted 结果。已接受激活响应先验提供的已验证目录、原挑战身份/阶段/启用摘要，再认证解封会话；错挑战、坏密文或额外字段拒绝。`prove_envelope` 在认证后返回密文用于下一阶段持久化，普通 `prove` 保留仅 Rust 解封的原行为。使用已保存的挑战/目录时可恢复原接受结果，不重新生成证明；错误仍保持未知结果。SDK 未接业务 IPC，页面没有申请凭据、密钥或会话令牌。

真实 HTTP/PostgreSQL 专项 11 项通过，含取消前置、回包丢失、原证明并发竞争、成功证明回包丢失后取消取回同一密文、原会话保留、权限与额度。当前交付是激活持久任务所需的服务端基础；本机原任务/取消意图持久化、租约协调、正常 Windows 档案和页面仍待实现。实际证据见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)，不关闭双 Windows、系统交互或独立审查。

## 2026-10-02 正式会话服务与明确协议切换

新增共享 `device_activation` 原语、Rust 类型化激活 SDK、服务器激活服务与 PostgreSQL 增量 18。原设备以既有会话和原 Ed25519 签名明确启用单聊 v3，签名绑定 origin/账号/原设备/目录版本和 head/原事件号；同一原事件幂等，启用不可撤销。旧单聊待收或未确认操作尚存时拒绝切换，原客户端仍需在后续页面接线时检查本机未确认任务并保存原启用事件。

| 入口 | 边界 |
| --- | --- |
| POST `/devices/messaging/enable` | 仅原设备、原签名、完整当前目录，原启用记录重试不重新生成 |
| GET `/users/:user/device_messaging` | 已认证公开状态及原启用签名，SDK 对照已独立确认根验证 |
| POST `/auth/v3/begin` | 账号密码、已有有效原授权阶段、客户端原编号与随机申请凭据；不替换设备/密钥 |
| GET `/auth/v3/:id` | 原申请凭据，原挑战及阶段/期限；不能查询消息或另一个申请 |

挑战 10 分钟，随机秘密和上下文以临时 Curve25519 密钥加密到当前设备，证明绑定完整挑战摘要和秘密哈希。当前目录变化或原阶段撤销拒绝未接受证明；已经接受的相同证明在当前阶段/密码状态及原会话仍有效时可重取原加密结果，不另签发会话。SDK 发送口令前检查已确认根、设备/阶段/参数，对返回挑战复核当前验签目录及启用签名。响应限 16 KiB、不跟重定向，未知字段和身份/版本/大小不符拒绝。

访问/刷新令牌装入与原挑战绑定的设备专属加密封套，服务端只存哈希、原证明摘要和密文；其他设备不能解封结果。令牌不进入页面，私密原语类型无 Debug，临时秘密/密钥及令牌有擦除路径，不代表完整内存取证。30 分钟访问和 30 天刷新沿用现有期限，刷新一次性消费并继承原授权阶段；撤销或密码变更后旧会话/申请凭据不能恢复。每账号最多 4,096 申请、8 个未完成活跃挑战，超限明确失败。

旧单聊投递与原设备切换共用稳定顺序的账号行锁；切换后旧 WS 资格、v2 新投递、旧编辑/撤回/回应/阅读回执的新提交明确拒绝，不向新设备扇出旧格式。双方必须明确启用才能新投递 v3；426 返回需要升级，不自动退回旧协议。原设备群仍可用，第二设备在群事务授权及共用旧接口前拒绝。旧 `/auth/login` 只可在未切换账号的原设备签发会话，第二端始终不能凭密码/公开公钥绕过证明；切换后的重登录走新证明。旧无签名设备删除不能绕过授权日志。

用户搜索和账号单公钥查询保持原设备身份，不因新增 operational 第二设备改变联系人指纹；完整设备授权仍读签名目录。未启用账号的单设备和群协议、旧迁移保持。实际 5 项激活 HTTP/PostgreSQL 和原 11 项 v3 联调通过，后者现在取得真实协议启用/双密钥会话，不再 SQL 插入第二端会话。Windows 加入档案的激活原请求/证明持久化、后台和业务 IPC/页面仍未接，不能据服务端会话交付勾选 T23 整体；原升级快照/离线备份不用于在线激活。

## 2026-10-02 单聊 v3 受认证 API 与消息协调器

新增 `messages/api.rs` 和 `messages/coordinator.rs`。API 只提供五类业务 HTTP，拒绝重定向、非规范编号/服务器范围、不绑定原摘要的回执及非法分页；原结果 32 KiB、补收 512 KiB 有界读取，未知长度分块也累计计量，ACK 必须收到 204。网络响应由不可从 JSON 构造的 Rust 包装类型绑定，随后仍由持久化核心验批次、历史目录及每个独立 ACK 签名；包装不是服务器签名或 SQLite 提交证明。私钥不进入 API/页面，运行时令牌由 Rust 暂存并擦除，错误不回显 URL、头或响应正文。

消息协调器默认要求原生 witness，按账号/设备及两组公钥固定 owner；开放显式随机测试配置，不因文件位于临时目录而默认降级。同步 SQLite/native/gate 锁不跨 await，网络串行锁是 Tokio 锁。本机操作和网络返回必须持有当前租约；轮换会话使旧结果失效但不解锁，锁定清会话，解锁也不能恢复旧代次。取消期间的原任务修订增加，旧接受/unknown 回包不能覆盖新意图；后续原结果查询仍可确认已经接受的同一批次。

首次文字准备前各同步一页自己/对方目录，尚未独立确认根返回 NeedsTrust，部分目录返回 Syncing；不根据包内目录自动信任根。准备在 Rust 生成编号并保存密文/签名；step 在查询前持久标记 publishing，先查原结果，再决定原包提交或取消 fence。目录冲突保留原包，禁止自动重签；用户显式取消后可准备新编号/新受众。错状态、超时、401/403/404/409 都不等同“未接受”，不清原包；只有绑定的 cancelled 响应才能结束未知结果任务。

取消请求作为 `cancel_requested` 保存在本机认证加密封套，修订和封套原子提交，原远端 wire 不变；重启继续查询/取消，不恢复发送。Prepared 从未发布可本机幂等取消，Publishing 必须取得远端终态。旧封套缺该字段按 false 读取，实际加密旧格式兼容短测通过；未改变历史 SQLite DDL或 witness 覆盖版本。旧读取器无法读取新增字段时应拒绝，不得抹去取消意图；没有宣称旧读取器可消费所有新封套。

每次 poll 最多发一个已落库的原 ACK、接收一个包，目录仍按一页推进；未知根、坏签名/阶段或不支持的媒体保留远端队列。只有文字通过公开文本接口返回，附件密钥/描述不会由该接口输出。收到包后仍有原 ACK 待发，has_more 会提示后续工作；远端空页也检查余下本机 ACK。poll 的 received 是处理包计数，不是新增消息/未读/通知事件；后续桌面连接按持久消息编号实现去重和可见性。当前未启动实际应用后台定时器或开放新 IPC。

6 项 API 短测、4 项协调器短测、1 项旧封套兼容用例，以及真实 PostgreSQL/HTTP/四份原生保护 SQLite 协调器联调通过。实际丢接受回包/原 ACK/取消 fence、重开、未知根及错误指纹、目录冲突、本人副本和第二端回复均有证据；operational 第二设备会话仍是 SQL 夹具，不是生产激活。下一步接明确激活、会话模式/旧队列及 Windows 生命周期与业务 IPC，维持第二端群禁止，再接旧操作/媒体/新备份/选定历史。双 Windows、系统交互及独立审查继续待验。

## 2026-10-02 单聊 v3 原子 HTTP 投递与独立 ACK

新增独立 `/direct/v3` 服务及 PostgreSQL 迁移 17，不修改旧迁移、WS v2 或群协议。仍需显式配置授权 origin；普通设备会话在事务内复核有效期、撤销、账号/设备及两公钥，并必须处于当前验签目录的原授权阶段。申请凭据不成为消息会话，授权记录不自动插入 operational 设备或开启普通登录；第二设备激活和桌面后台接线继续后续实现。

| 入口 | 行为 |
| --- | --- |
| POST `/direct/v3/batches` | 校验完整当前目录、签名、受众及阶段链；同一事务保存整批次、全部设备队列及 head，原 digest 重试返回原结果 |
| GET `/direct/v3/batches/:id` | 仅原发送账号/设备会话查询，必须带原 digest；返回 unknown、cancelled 或原 accepted 时间/摘要及已签 ACK |
| POST `/direct/v3/cancel` | 提交原签名批次并锁同一账号范围；已接受则返回原接受，未接受则记录摘要绑定的永久取消 fence，迟到原包只能返回 cancelled |
| GET `/direct/v3/pending` | 当前设备、当前原授权阶段及双方联系策略核对后按队列顺序分页；最多 100 项/512 KiB，未 ACK 原包保持可补收 |
| POST `/direct/v3/ack` | 8 KiB 请求上限；独立目标签名、原阶段、完整批次 digest 和 processed/rejected 绑定，只结束该设备队列；相同 ACK 原字节重试幂等 |

unknown、超时、HTTP 冲突或过时目录不能用于客户端 `confirm_unaccepted`；只有上述取消 fence 的绑定结果能确认原包不会在后续被接受。取消可以验历史原目录，不能新签替代原任务；取消记录每账号最多 1,000 项，超限明确失败且不伪装取消成功。批次最多 256 KiB，当前服务仅接 text 类型；attachment/voice 需要后续媒体授权，明确拒绝而非保存未经授权的描述。

账号行按稳定顺序锁定，与授权/撤销串行；设备队列额度锁先于联系策略锁，兼容旧 v2 队列的锁序。两版本共享每设备 1,000 项/10 MiB 待收上限，两侧检查都包含新旧负载；配额失败不落部分受众或推进 head。联系策略读取持有同一 advisory namespace，阻止双方拉黑变更穿越检查。每设备每分钟最多 120 次请求，资源/存储失败保留原任务。

接受回执和序号保留用于结果查询/重复编号隔离；每目标独立 ACK，仅在全部目标已 ACK 或撤销不再有资格时清除整批次密文。撤销同事务使原目标待收记录 ineligible，释放不再需要的密文，并使已激活投影的 operational 设备和全部会话失效；新授权阶段不接旧队列。已下载本机正文保持既有可见性规则，不远程删除。ACK 依据已接受批次重建精确签名历史前缀，不为未接受客户端输入自动钉根。

9 项真实 HTTP/PostgreSQL 短测通过，包括两账号/四套密钥、整批次/独立 ACK、原结果重试、竞争取消、共享额度、阶段撤销/重新加入、65 条补收及分页字节限制。新增 HTTP 回执接入 Windows 原生保护 SQLite 的短联调通过：丢失结果后重开原包，落库后原 ACK 重开/重试，隐藏后重复收件不复现正文。第二设备 operational 会话由测试夹具显式写入，不是生产激活或四个实机客户端；普通后台 API/租约仍待接。实际报告见验收记录，双 Windows、系统交互及独立协议审查继续待验。

## 2026-10-02 单聊 v3 原批次与收件持久化

## 2026-10-02 单聊 v3 完整收件协议基础

`shared/src/direct_message.rs` 新增类型化目录快照、批次头、逐设备密文、链 head 与签名 ACK，独立于原 `SignedEnvelopeV2`。发送者根/第二设备与对方根/第二设备都使用各自密钥；目标是对方全部有效设备及发送者另一台设备，最多三份，源设备已有本机发送记录，不再给自己投递。目标按账号/设备排序，必须与已验签的两个目录完全相等，不能遗漏自己的副本、只发某个对方设备、重复或插入未知设备。

目录快照绑定原根哈希、版本、完整 head、公钥列表和每设备授权阶段（根用 anchor hash，第二设备用 grant event hash）。签名域 `LiteSeal/direct-batch/v3` 以长度分隔绑定 origin、两账号、规范会话、原消息/发送设备、两侧快照、序号/前序、时间、类型、内容承诺及全部目标密文长度/摘要。批次 digest 包含签名，所有副本使用同一链 hash；幂等重试必须保留原批次字节和 digest，不能根据原编号重新加密。

每份密文中含完整头的上下文 hash、同一私密随机 32 字节盐和正文长度/字节；公开 SHA-256 内容承诺也绑定这些值。解密检查上下文和承诺，拒绝同一发送者重签后的跨消息移植或不同目标正文替换；公开格式不包含确定的正文 hash。明文/盐临时缓冲擦除，Curve25519 私公钥派生与 Ed25519 证明在发出密文前核对。复用项目已有 libsodium [`crypto_box_easy` 与公钥派生](https://raw.githubusercontent.com/jedisct1/libsodium-doc/master/public-key_cryptography/authenticated_encryption.md)及[分离签名](https://doc.libsodium.org/public-key_cryptography/public-key_signatures)；上层承诺/链阶段是本项目设计，不代表 libsodium 文档或本机测试已替代独立协议审查。

链阶段由 origin/会话/发送设备和两个目录完整快照确定。成员变化开启新阶段的第一条（序号 1、空前序），让新加入设备从新消息开始校验；同一阶段继续精确匹配上条 digest/递增序号。调用者按阶段查已持久化 head，不能因为不匹配而清空旧 head；目录回退由平台高水位和实时事务拒绝，不能把新阶段当成绕过版本检查。历史验证只能使用当前已可信链的精确历史前缀，不回退持久高水位；完整接收路径仍需判定服务器已接受证据和当前收件资格，不能从独立 codec 验签直接授予补收权限。

ACK 域 `LiteSeal/direct-ack/v3` 绑定 origin、原编号/完整批次 digest、目标账号/设备、原授权阶段与 processed/rejected，由该目标独立签名；自己的副本 ACK 不能冒充对方。它证明目标报告的结果，不证明 SQLite 已提交；后续核心必须先持久化处理/拒绝再签发，服务端必须检查当前会话/资格并仅删除该设备队列。签名/目录未验证的批次不能产生本 ACK；已认证而正文损坏可在隔离记录持久化后拒绝 ACK。

当前限正文 16 KiB、每份密文 16 KiB + 116 字节（内部头/nonce/MAC），新批次 JSON 256 KiB、ACK 8 KiB，未知字段/版本/非法 ID、长度或链形态明确拒绝。text 需 UTF-8；attachment/voice 仅是加密描述类型，实际文件/时长校验仍由后续核心媒体业务负责。旧 WS 限制与接口不改，不能把本大小直接用于旧入口。

新增 9 项短测/四套独立 Rust 密钥通过，覆盖根/第二设备组合、完整集合、移植/篡改、撤销/重新加入、新成员阶段、原字节重试、长度/错密钥和独立 ACK。本次尚未接 `ClientMessage`/HTTP/WS、PostgreSQL 原子投递、SQLite 收件/待发或正常激活；下一增量接持久化历史前缀/阶段与原批次，随后事务投递/独立 ACK、会话、Windows 和选定历史。不能把纯协议测试当作多设备功能交付完成。

## 2026-10-02 Windows 授权流程默认高水位

原设备与加入档案业务命令现在通过 `open_protected` 默认启用外部记录；普通构造和自定义 keystore 构造都选择生产存储，不能因测试路径自动降级。新档案在保存原申请前建立保护，首次成功返回时原任务已使代次从 0 推进到 1。重开、切档案、账号/令牌变化和暂停后重建继续使用同一数据库/SID 绑定的系统记录；同库不同 scope 的合法修改更新整体摘要，不被误判为当前身份回退。安全校验失败由固定业务错误提示保留数据，既有任务不被重建。

随机隔离配置仅用于 Rust 测试和 sidecar 私有命令行，要求明确数据库/keystore 文件。进程内重开共享配置，最后清理只作用已注册的精确随机目标；子进程重开显式传入同一 namespace，停止全部进程后单独清理。它们不在 stdio 业务协议、preload、页面或离线档案接口中；生产拒绝删除/重置。清理不枚举系统凭据，不读取身份文件/数据库内容，也不删除目录数据。

## 2026-10-02 外部高水位核心与 Windows 适配

新增 `witness` 保护引擎，覆盖同一 SQLite 中全部账号/设备 scope 的授权根、签名日志、加密控制任务及加入绑定，包含表/索引/触发器结构摘要；普通聊天表不在此防回滚范围。每次读写核对外部状态，修改递增代次，根确认与意向保存仍原子提交。首次接入只能登记本机现存状态，不证明登记前的新鲜度；登记后缺少外部记录或 marker、状态/结构不匹配均拒绝，不能自动重置。`protect` 是显式核心接口；本次尚未接到桌面协调器的默认构造，不能声称所有产品操作已经防回滚。

SQLite 与系统存储间使用 DPAPI 写前变更日志：先同步确定的白名单行补丁，再保存外部 pending，SQLite FULL 同步提交，最后完成外部 head。重开时只接受原 before/after 摘要；数据库已提交则完成记录，否则重放原编号/原密文，不重新签名。缺失/损坏/不匹配日志保留数据并拒绝。日志限 4 MiB、每次最多 256 行变更、保护状态限 512 MiB；资源超限明确失败。日志只含公开授权证据及已加密任务，不含明文私钥或聊天正文。

该机制信任 Windows 用户凭据存储仍保留最新状态，能拒绝仅应用目录/SQLite 的整体回退；Credential Manager 可由该用户修改，它不是硬件单调计数器。数据库和系统凭据一起恢复/替换、首次登记前回退、用户/路径迁移需要远端或硬件锚及单独恢复设计，不能宣称已防住。T22 不携带这些记录，也不用于在线激活。9 项故障引擎、4 项原生入口（含一个子进程 helper，主用例实际启动子进程）及备份往返短测通过，实际证据见验收记录。下一增量接桌面默认防护、档案创建/整理生命周期与隔离测试清理，再实现完整设备收件协议和激活。

## 2026-10-02 取消与授权竞争

加入任务或原挑战已请求取消，但远端授权先被接受时，必须先从原根完整验链并确认原意向/挑战的授权证据，终态是已完成；用户如需移除授权应在原设备撤销。不能把服务端已授权状态响应单独当作接受证据，也不能持续冲突或显示取消成功。

## 加入与撤销

1. 第二设备用账号密码申请加入意向并签署一次性挑战；申请会话不能读消息/历史。每账号最多一个有效意向，有效期 10 分钟。
2. 原设备显示第二设备两组指纹，用户通过可信渠道核对。原设备向新加密公钥发送随机认证挑战，新设备解密后以新签名私钥证明收到，绑定服务器/账号/意向，拒绝跨设备重放。
3. 原设备验签并签发授权。服务端事务锁账号，核对有效原会话、根签名、挑战、版本、上限和新设备签名，原子保存事件/设备并授予新会话正常权限。
4. 响应丢失时查询或重试原意向/授权编号和签名内容，不自动创建新身份。

撤销由原设备确认并签署；服务端同一事务撤销目标 HTTP/WS/刷新会话、队列和后续资格，并关闭现有 WS。离线撤销后重新上线不能补收后续消息。已经下载的历史不能远程擦除。

新设备默认无旧历史，不迁移待发、定时、上传、ACK；草稿/静音/定时任务各自独立。旧消息编辑/撤回仍仅原发送设备按现有时限执行。旧客户端不支持新授权链/信封时禁止开启多设备；未开启账号继续原单设备协议，密码登录不得成为隐式设备替换。

## 实现前门槛

两台 Windows 验证：两组公私钥证明、指纹核对、响应丢失、重放/过期、并发加入/撤销、错误根、授权链乱序/篡改、设备上限、旧客户端拒绝、撤销旧 HTTP/WS/refresh、离线撤销、新旧历史隔离、迁移中断/损坏和原发送设备编辑权限。

独立审查重点为授权根长期持有、设备目录回滚、收件集合/事务竞争，以及迁移正文与原证据的信任差异。审查和可运行验证通过前，不开放普通用户多设备登录。失去原设备但持有 T22 备份时只能离线阅读；在线根恢复必须另行设计。
