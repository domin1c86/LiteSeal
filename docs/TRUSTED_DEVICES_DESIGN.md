# T23 两台 Windows 可信设备：设计与授权基础

## 2026-10-03 媒体整理的身份与状态边界

get_direct_media_storage/clear_direct_media_cache 只接受当前正常身份的 scope；按会话参数为规范账号编号。Rust 认证密钥和受保护任务元数据，Prepared 必须核对原任务或保留的已接受历史，未知发布/待发/正在下载不清理。批量操作在全部分类成功后写受保护清理标记并删除密文，任何元数据校验失败不开始删除；孤立密文仅在整理全部会话时按当前身份范围收集。

统计不会暴露隐藏正文、媒体名称、密钥或路径。共享额度只报当前账号在当前数据库的总量，清理仅处理选中 v3 范围，不借此整理其他身份、旧单聊或群。SQLite 文件占用是当前档案整个数据库及 WAL/SHM 的观察值，不能解释成当前会话的物理载荷或保证清理后立即缩小。清理后主进程退役旧预览，界面丢弃暂停后迟到统计；服务端协议与迁移不变。

## 2026-10-03 桌面媒体路径与预览生命周期

新增公开媒体业务命令携带选中档案的不透明 notification_scope，Rust 校验它与当次正常身份/代次一致；暂停或恢复后的旧范围拒绝。只有 main 可以调用 stage_direct_media/write_direct_media 私有路径命令，preload 不暴露它们。拖入 File 的路径由 webUtils 获取，录音 Blob 仅通过主进程 IPC 转成临时文件；到 Rust 的 stdio 请求只含路径和业务字段。

暂存预览只允许本身份 Staged/Uploaded 上传任务，认证完整密文；不能借暂存入口读取下载、取消、已准备或隐藏内容。已发送消息使用原可见认证描述。Rust 输出 create_new、写入/同步后重查范围和可见性，返回公开信息与明文内容摘要，不返回路径或密钥。主进程拥有临时文件和预览映射，页面只持有随机句柄；每次请求核对当前范围/设备代次、消息或暂存状态、文件长度和摘要，再提供白名单媒体类型及单段 Range/no-store/nosniff 响应。隐藏、取消、切身份及系统暂停退役句柄。

另存为排他提交，不覆盖已有文件；预览临时文件可能包含认证后的媒体正文，但不含聊天导出或私钥，关闭/退役删除。真实进程强杀/磁盘满/权限拒绝与临时文件回收、真实系统麦克风及播放没有本批证据，继续待验收。现有服务器协议/迁移、原受众授权和 T22 格式不变。

## 2026-10-03 原可见消息的下载与只读缓存

下载准备从受保护历史验证原批次及认证描述，隐藏/拒绝记录不提供密钥。下载任务记录原设备授权摘要并按步骤检查当前本机目录，服务端仍逐次检查当前资格与原受众。已缓存副本读取不要求当前联网资格，但必须属于当前身份、原可见消息及相同描述，符合已下载副本不远程删除的边界。

任务增加 download 标记及 Downloading/Cached/Failed/Unavailable 阶段；旧上传任务缺少标记时按 false 读取。下载前缀摘要由本机采样并认证加密保存，只能证明已存前缀未改动，不能替代原描述的全量摘要/MAC。先提交密文块、后提交受保护进度，原生恢复可沿预先提交的块继续；配额失败或错误块不推进。全量验证失败持久 Failed，取消/错误后显式重试保留原编号及描述，完整读取每次重新认证，不输出文件密钥。

隐藏原记录时同一事务取消 Downloading，修订保护迟到网络结果；公开信息、任务状态、缓存正文均拒绝隐藏记录。签出不发网络请求即可读已有缓存，远端 403/404 将下载标为不可用并保留历史。缓存清理保留原编号标记，后续下载只能从原消息恢复描述，下载记录不能借用暂存/发送入口。原文件/语音的媒体字节尚未通过桌面 IPC，预览 URL 的身份/锁定生命周期在下一阶段验证。

## 2026-10-02 受保护媒体任务与独立密文缓存

媒体原编号绑定身份/聊天账号、随机描述、文件密钥、完整摘要与分块摘要。加密任务记录沿用已覆盖的 device_control_tasks；所有记录标记 terminal=1 以避免借用设备控制任务的单待发索引，实际媒体阶段/进度由认证密文和修订决定。独立 direct_v3_media_chunks 保存每块至多 1 MiB 密文；它是可丢弃缓存，不进入有限原生补丁日志。缓存表/主键结构逐次严格验证，拒绝额外索引/触发器；块长和受保护摘要不符则失败，不用于上传/准备。逻辑缓存预算按同库账号与既有单聊/群合计，不代表 SQLite 文件立刻缩小。

完整密文先提交，描述后提交；故障时原生恢复的描述仍能引用之前提交的密文，未引用块可回收。准备媒体先完整认证，再与原签名批次在一笔受保护写入标记 Prepared。普通媒体 prepare 入口不能绕过上传。已经 Prepared 的请求永远返回原任务，目录冲突保留原批次，不重签。上传一次一块并使用独立网络锁；租约/修订和取消保护迟到回复。上传未准备时远端 404 可重置原进度，保持原密文和编号；已准备阶段不隐式改受众。

清理只允许本地取消或服务端已确认接受/取消的任务，未知发布不清理。保留加密的原编号清理标记并抹去该任务描述密钥，原消息/结果仍保留；已接受正文中的加密描述仍属消息历史。收件对已知媒体类型先解析/认证描述形状，失败记录 Rejected 并持久拒绝 ACK，不将文件字节交给页面；完整附件认证和下载权限在下一阶段接入。隐藏仍通过原历史规则检查，未联网缓存/播放与桌面完整交互尚未交付。

## 2026-10-02 Rust 媒体传输接口边界

共享 DirectApi 增加原对象创建、分块上传/下载和媒体 Submission 发布；MediaObject 只持有 Rust 内的设备/对象编号与公开密文引用。创建结果绑定原编号；上传严格分块长度且只确认 204，下载必须等于原引用的对应分块长度，未知长度响应同样逐块限额。发布验证原 origin/编号、签名绑定，并沿原批次摘要验证接受收据；不自动改编号或重加密。HTTP 不跟随重定向、不把响应正文写到日志。

分块返回值只是密文，完整对象仍须通过 Descriptor 的摘要/MAC/长度/格式验证后才能进入可用缓存或显示明文。当前接口尚未驱动持久任务、收件 ACK 或页面显示；独立短测与真实 PostgreSQL 四设备下载通过，不能替代后续协调器与 Windows 生命周期验证。服务端协议和迁移保持本轮之前的版本 22。

## 2026-10-02 独立 v3 媒体绑定与原授权

文件 ID 与根批次 ID 相同。描述版本 1 的文件名、MIME、大小、时长、随机密钥和摘要进入既有批次逐设备密文；额外 Submission 仅公开密文 size/hash，以独立域签署原批次完整摘要和该引用，原文字签名/收据不变。bind 在原批次上生成相同绑定，不重新加密；私钥和文件密钥不作为页面接口。描述拒绝未知字段、错编号/类型、非法名称、错误密钥长度和越界参数。完整缓存须通过摘要、secretbox MAC、长度及格式验证后才使用。

对象创建记录原上传设备与授权，尚无收件权限；发布在原批次事务内固定发起设备及双方原目录成员/授权摘要。下载逐次验证当前正式设备资格、联系策略和该对象的原授权；后来加入或撤销后重新加入不能继承旧资格。已下载副本不远程删除。服务端只限制大小与公开绑定，60 秒为 Rust/客户端声明时长检查，不声称检验加密音频实际时长。

迁移 22 保存对象、分块、原受众及独立发布绑定墓碑。所有附件共享每账号 512 MiB/2000 配额；v3 账号行使用 FOR NO KEY UPDATE，仍排斥授权变更，同时兼容外键 KEY SHARE，以免旧附件持有配额锁后等待账号行造成循环。锁兼容性依据[PostgreSQL 16 官方说明](https://www.postgresql.org/docs/16/explicit-locking.html#LOCKING-ROWS)；实际旧附件/v3 同时争用最后一个对象配额用例已在标记专用 PostgreSQL 16.14 通过，512 MiB 边界也已实跑；说明或编译没有被当作验证。

客户端任务、缓存与 IPC 尚未接入，新接口不表示界面媒体已可用。既有接收协调器继续 Unsupported 并保留待收；T22 拒绝含 v3 新历史的旧导出。实际工程与密码学证据见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)。


## 2026-10-02 会话读取与通知范围

共享 Store 在当前拥有者范围保存加密会话设置：单调已读边界、通知领取边界与静音修订。账号过滤在分页限额前执行，默认全会话历史仍可读；明确已读必须提供此账号可见的认证消息编号，隐藏/其他账号编号拒绝。只统计 processed/incoming；标记包含边界以前历史，不作为远端已读回执、不发网络请求。

旧消息见证投影没有覆盖 rowid，现用既有 device_control_tasks 独立 order 范围绑定记录编号与游标；新记录原子绑定，旧受保护内容首次按当前顺序补建，读取/通知前检查。不会改写历史 schema。会话设置和排序沿原生见证事务、故障恢复与原身份范围隔离。

后台只领取未读、未静音、未隐藏的新来信，每个已核对账号最多一个通用提示；领取先持久后返回。提示失败/响应丢失不回退领取、不重发提示，可靠事实仍是本机历史与未读。通知不调用旧协议联系人接口；Shell 从 Rust 验证不透明 scope 和当前账号，最新上下文请求胜出，旧点击、迟到结果、锁定和休眠拒绝。前台判断包含焦点、页面可见性与面板遮挡。静音只影响此设备，不删除内容或改变 ACK。实际短测见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)，媒体、操作权限、备份与历史授权未关闭。


## 2026-10-02 草稿修订、消费标记与原任务幂等

`messages/drafts.rs` 使用既有 `device_control_tasks` 表的独立拥有者 scope/peer 槽，正文认证加密，校验固定域/v1、范围、账号、修订及原准备编号；外部 witness 防回退。每个身份最多 128 个账号草稿，正文仍以 64 KiB UTF-8 为界，保存修订必须匹配，空槽以修订 0 起始；不依赖会话能力作本机加密密钥，也不向页面返回密钥。

`get_direct_draft` 和 `save_direct_draft` 只作用选中身份和已 pin 账号。`prepare_direct_text` 携带 `draftRevision` 后，共享核心在同一受保护写中核对正文/修订、保存原批次并把草稿变为空正文及原准备编号，失败不可只清正文或只留任务。消费后的前一修订重试只读取原任务，正文不同、新保存修订或已整理结果均不能借旧修订生成新编号；已有草稿的旧无修订桌面调用明确拒绝。

界面保存队列保留每次响应期间的新编辑，发送前等待当前正文保存并携带修订。准备响应丢失时读取消费标记，只有对应修订才清理输入；新编辑不能被旧成功清空。切换账号/打开档案管理前保存，失败阻止离开且保留此处正文；过时修订既不覆盖存储中的新正文，也不替换未保存输入。重新读取有未保存正文时需明确确认；资源恢复可重试相同修订。锁定暂停并清空视图，不接受迟到读/写结果；尚在保存中的最后输入不当作已保存，强制进程终止的真实时序仍待系统验收。

实际核心、真实 Rust/合成 HTTP、模拟 Chromium 的范围分别见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)。T23 其余聊天/媒体/历史授权仍未关闭，草稿功能不代表完整备份或系统生命周期完成。

## 2026-10-02 桌面 v3 文字协调器与核对入口

`commands/direct.rs` 只捕获选中正常范围。缓存绑定持久选择、完整身份摘要与运行代次，能力变更只由 Rust 更新协调器会话；私钥、附件描述或会话能力不作为页面输入。原设备须已有原生保护正式记录才给 v3 协调器能力，单纯启用不借旧 beta 令牌。加入身份自身根来自原已验证 ticket/授权证据，不能用加入设备自身公钥冒充原根；数据库沿原档案独立路径。

九个公开命令为 `get_direct_chat`、`get_direct_history`、`inspect_direct_peer`、`confirm_direct_peer`、`prepare_direct_text`、`direct_task_step`、`cancel_direct_task`、`forget_direct_task`、`hide_direct_message`。候选仅查询同原点/账号的公开根，缓存与当前范围/能力绑定；用户须从对方原设备独立取得并明确核对完整根指纹，确认才 pin，目录之后由共享核心验链。最多 128 个对方根与待核对候选，重复同根仍可查询，不能替换已 pin 的不同根。

主进程私有 `process_direct_chat` 每两秒串行调度，页面/离线窗口不能调用。一个周期沿一个原任务查询/提交并处理有限收件与一个持久 ACK，已落库后才推进确认；总网络步骤有 50 秒观察上限，超时保留原编号而非成功或失败重签。冲突不后台新建，明确取消优先处理；旧 lease 在锁定/清除/切范围时失效，更新能力时也旋转。加入本机会话清除和原身份保存/清除先退役消息协调器，再改变能力；迟到网络回包不能提交旧 lease。

历史按受保护本机行序游标分页，每页六条，验签/解密成功文字才返回；未知类型/被隔离正文不输出密钥，隐藏的记录从历史排除，重放仍只补原 ACK。原任务与消息历史分开，明确整理已接受任务不删除消息；取消记录保留。界面提供基础文字路径，原设备另有旧历史/群聊入口，旧消息仍按原协议标识，不升级为 v3 验证。当前没有新未读/通知、持久草稿或新媒体/编辑/备份接线，不能称为 T23 完成，证据见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)。

## 2026-10-02 显式选择的持久记录和运行范围

共享 `profiles/selection.rs` 在现有受保护任务表保存 v1 选择槽，正文 DPAPI 保护、外部 witness 检查整行与代次；不新增迁移。绑定包含严格 root/join 目标和公开身份范围摘要，实际来源由 Rust 重新读取，调用者不能提供数据库路径、密钥、能力或授权替代物。`get_normal_profile` 返回公开身份、范围指纹、会话存在/到期/资格及可用性；`select_normal_profile` 必须给当前代次和完整指纹，`clear_normal_profile` 写入明确空选择。未有选择槽时兼容既有原设备；一旦明确停止或已选身份不可用，不自动回退。

桌面选择写门禁等待原范围请求完成后断开旧中继，核对提交租约和持久代次再写入。切换退役设备/续期/正常运行租约、旧群令牌和备份；主进程清除通知上下文、关闭离线窗口并推进 IPC 代次。旧结果与文件对话框结果不能晚到后进入新范围。锁定/休眠保留选择但暂停操作，解锁重新核对；清除选择仅停止本机使用，不声称远端家族退出。

加入正常档案由原 ticket/授权证据和自身完整会话读取，设备编号沿服务端原授权，身份文件与独立数据库保持。加入续期不依赖另一个本机原设备身份；后台仅捕获选中目标及其数据库/能力，步骤结束重新核对持久选择与运行代次。未选中档案没有自动请求，撤销或本机清除会话后没有新后台请求。根管理仍明确使用原身份，旧正常聊天/群/存储/备份导出在加入或空选择范围被拒绝，不能把旧主数据库交给加入界面。

启动先查询选择，加入或明确空选择只显示档案管理首页；旧 App 在切换时卸载、重新挂载时使用对应代次，指纹/代次错误显示问题而不替换身份。登录与账号面板提供选择入口；加入首页支持自身续期、加入任务及只读离线恢复。当前首页尚无 v3 消息后台或历史展示，这些须继续接共享协调器，不能据此称为第二端普通聊天完成。短测以[验收记录](P0_P1_ACCEPTANCE_RECORD.md)为准。

## 2026-10-02 续期业务目标、界面与调度

`get_session_refresh`、`prepare_session_refresh`、`session_refresh_step`、`cancel_session_refresh`、`forget_session_refresh` 只接受 `{kind:"root"}` 或 `{kind:"join",profileId}`；未知字段和秘密/路径注入拒绝。根范围来自原 DPAPI 身份，加入范围来自已保存的独立正常档案与原 ticket/任务拥有者。当前视图只有账号、设备、会话编号、代次、到期时间、存在/资格标记；任务视图没有能力、证明秘密或密钥。

## 2026-10-02 单聊 v3 完整收件协议基础

`shared/src/direct_message.rs` 新增类型化目录快照、批次头、逐设备密文、链 head 与签名 ACK，独立于原 `SignedEnvelopeV2`。发送者根/第二设备与对方根/第二设备都使用各自密钥；目标是对方全部有效设备及发送者另一台设备，最多三份，源设备已有本机发送记录，不再给自己投递。目标按账号/设备排序，必须与已验签的两个目录完全相等，不能遗漏自己的副本、只发某个对方设备、重复或插入未知设备。

目录快照绑定原根哈希、版本、完整 head、公钥列表和每设备授权阶段（根用 anchor hash，第二设备用 grant event hash）。签名域 `LiteSeal/direct-batch/v3` 以长度分隔绑定 origin、两账号、规范会话、原消息/发送设备、两侧快照、序号/前序、时间、类型、内容承诺及全部目标密文长度/摘要。批次 digest 包含签名，所有副本使用同一链 hash；幂等重试必须保留原批次字节和 digest，不能根据原编号重新加密。

每份密文中含完整头的上下文 hash、同一私密随机 32 字节盐和正文长度/字节；公开 SHA-256 内容承诺也绑定这些值。解密检查上下文和承诺，拒绝同一发送者重签后的跨消息移植或不同目标正文替换；公开格式不包含确定的正文 hash。明文/盐临时缓冲擦除，Curve25519 私公钥派生与 Ed25519 证明在发出密文前核对。复用项目已有 libsodium [`crypto_box_easy` 与公钥派生](https://raw.githubusercontent.com/jedisct1/libsodium-doc/master/public-key_cryptography/authenticated_encryption.md)及[分离签名](https://doc.libsodium.org/public-key_cryptography/public-key_signatures)；上层承诺/链阶段是本项目设计，不代表 libsodium 文档或本机测试已替代独立协议审查。

链阶段由 origin/会话/发送设备和两个目录完整快照确定。成员变化开启新阶段的第一条（序号 1、空前序），让新加入设备从新消息开始校验；同一阶段继续精确匹配上条 digest/递增序号。调用者按阶段查已持久化 head，不能因为不匹配而清空旧 head；目录回退由平台高水位和实时事务拒绝，不能把新阶段当成绕过版本检查。历史验证只能使用当前已可信链的精确历史前缀，不回退持久高水位；完整接收路径仍需判定服务器已接受证据和当前收件资格，不能从独立 codec 验签直接授予补收权限。

ACK 域 `LiteSeal/direct-ack/v3` 绑定 origin、原编号/完整批次 digest、目标账号/设备、原授权阶段与 processed/rejected，由该目标独立签名；自己的副本 ACK 不能冒充对方。它证明目标报告的结果，不证明 SQLite 已提交；后续核心必须先持久化处理/拒绝再签发，服务端必须检查当前会话/资格并仅删除该设备队列。签名/目录未验证的批次不能产生本 ACK；已认证而正文损坏可在隔离记录持久化后拒绝 ACK。

当前限正文 16 KiB、每份密文 16 KiB + 116 字节（内部头/nonce/MAC），新批次 JSON 256 KiB、ACK 8 KiB，未知字段/版本/非法 ID、长度或链形态明确拒绝。text 需 UTF-8；attachment/voice 仅是加密描述类型，实际文件/时长校验仍由后续核心媒体业务负责。旧 WS 限制与接口不改，不能把本大小直接用于旧入口。

新增 9 项短测/四套独立 Rust 密钥通过，覆盖根/第二设备组合、完整集合、移植/篡改、撤销/重新加入、新成员阶段、原字节重试、长度/错密钥和独立 ACK。本次尚未接 `ClientMessage`/HTTP/WS、PostgreSQL 原子投递、SQLite 收件/待发或正常激活；下一增量接持久化历史前缀/阶段与原批次，随后事务投递/独立 ACK、会话、Windows 和选定历史。不能把纯协议测试当作多设备功能交付完成。

## 2026-10-02 取消与授权竞争

加入任务或原挑战已请求取消，但远端授权先被接受时，必须先从原根完整验链并确认原意向/挑战的授权证据，终态是已完成；用户如需移除授权应在原设备撤销。不能把服务端已授权状态响应单独当作接受证据，也不能持续冲突或显示取消成功。

在从未签署意向的任务上，凭据不可用可结束本机草稿并清除凭据，持久标记 `local_abandonment`；这不证明远端删除。未发布意向使迟到的开始请求无法授权，可能留下等待期限结束的占位申请。已签署意向的任务不得仅根据 401 结束本机记录。新增对照和真实双方竞争短测见验收记录；加入端视图必须保留此区别。

- 同编号同字节重试幂等；已撤销后重试旧授权返回既有链状态，不恢复设备。相同编号异内容、并发版本、错根、过期实时提交和证明移植均拒绝。历史回放按当时已签名时间验链，不因当前时间超过意向期限而丢弃已接受授权。
- 每根链最多 4096 个事件，避免无界目录回放；达到上限拒绝新事件。本切片不解决整份本机数据回滚，需要后续持久高水位、目录协议和独立审查。

9 项授权测试及离线示例通过，shared 全部 59 项测试、格式和 shared/all-targets Clippy 通过。保留既有 LNK4098 链接警告。下一步持久化验链，再接入受限意向/授权/撤销事务、单聊多设备信封和桌面；未交付这些部分前不将 T23 认定完整可用。

2026-09-30：设计稿，本轮没有开放第二设备登录、增加服务端接口或执行迁移。现有单设备限制继续生效，T22 离线档案不代替设备授权。

## 首个切片与身份

每账号最多两台 Windows，支持原设备在线授权、独立设备密钥、单聊新消息、用户选定的单聊历史迁移和第二设备撤销。原设备保留群能力；第二设备明确显示“群聊仅原设备可用”。现有群按账号绑定单设备，群多设备需另做成员/设备阶段及收件集合设计。

原设备已被联系人钉住的 Ed25519 公钥作为首版账号授权根。对应私钥仅留原设备；第二设备生成独立加密/签名密钥，不能复制原设备私钥。首版不允许第二设备替换/撤销授权根，不提供根轮换或凭密码/管理员重置恢复根。

授权域 `LiteSeal/device-grant/v1` 绑定服务器 origin、账号、设备编号、两组公钥、挑战、到期、单调版本和前序哈希。撤销延续同一链。客户端从原已信任根验链，服务器返回的公钥本身不是信任锚。

## 加入与撤销

1. 第二设备用账号密码申请加入意向并签署一次性挑战；申请会话不能读消息/历史。每账号最多一个有效意向，有效期 10 分钟。
2. 原设备显示第二设备两组指纹，用户通过可信渠道核对。原设备向新加密公钥发送随机认证挑战，新设备解密后以新签名私钥证明收到，绑定服务器/账号/意向，拒绝跨设备重放。
3. 原设备验签并签发授权。服务端事务锁账号，核对有效原会话、根签名、挑战、版本、上限和新设备签名，原子保存事件/设备并授予新会话正常权限。
4. 响应丢失时查询或重试原意向/授权编号和签名内容，不自动创建新身份。

撤销由原设备确认并签署；服务端同一事务撤销目标 HTTP/WS/刷新会话、队列和后续资格，并关闭现有 WS。离线撤销后重新上线不能补收后续消息。已经下载的历史不能远程擦除。

## 接口与数据流

拟新增 `/devices/join_requests`（申请/查询/取消）、`/devices/grants`（授权）、`/devices/revoke`（撤销）、`/users/:id/device_manifest`（可验证版本链）。页面仅传类型化业务操作，不能提交私钥或任意签名事件。PostgreSQL 增加意向、事件和授权版本；SQLite 增加 origin/账号/设备隔离与信任链。迁移保留原库和根指纹，失败保持原单设备状态。

多设备单聊采用协商后的新信封版本，绑定发送设备证书、收件授权版本与完整设备集合，每设备一份密文，服务端整个批次原子接受或拒绝。加入/撤销与提交按授权版本协调。未知结果仅查询/重试原批次；明确未接受且版本过期时，才允许显式重建。客户端验根授权、设备签名、链并落库后 ACK，各设备游标独立。

历史迁移由原设备按用户选定会话/时间范围创建认证加密流，绑定两设备、授权版本、范围、顺序及到期；中继只存密文。新设备不用原私钥，解密后以自己的本机身份重加密。保留原消息/变更证据，但正文是受信原设备迁移，标记 `authorized_history_transfer`，不能伪称新设备收到的原始 `verified_v2`。删除/撤回/附件授权规则继续生效。

新设备默认无旧历史，不迁移待发、定时、上传、ACK；草稿/静音/定时任务各自独立。旧消息编辑/撤回仍仅原发送设备按现有时限执行。旧客户端不支持新授权链/信封时禁止开启多设备；未开启账号继续原单设备协议，密码登录不得成为隐式设备替换。

## 实现前门槛

两台 Windows 验证：两组公私钥证明、指纹核对、响应丢失、重放/过期、并发加入/撤销、错误根、授权链乱序/篡改、设备上限、旧客户端拒绝、撤销旧 HTTP/WS/refresh、离线撤销、新旧历史隔离、迁移中断/损坏和原发送设备编辑权限。

独立审查重点为授权根长期持有、设备目录回滚、收件集合/事务竞争，以及迁移正文与原证据的信任差异。审查和可运行验证通过前，不开放普通用户多设备登录。失去原设备但持有 T22 备份时只能离线阅读；在线根恢复必须另行设计。
