## 2026-10-03 T23 Windows 媒体入口与预览句柄

录音复用现有组件，v3 走 Blob/主进程临时文件；保留 60 秒/11 MiB、试听、丢弃、失焦停止及暂停/卸载释放设备。实测范围为 Rust/主进程短测、真实 Chromium 模拟业务/麦克风和既有真实库/群回归，见[验收记录](P0_P1_ACCEPTANCE_RECORD.md)。真实麦克风/播放、系统窗口与双 Windows、强杀后的临时预览清理仍待验收。统一 v3 存储统计/整理、已准备上传过期恢复、原发送设备操作、v3 备份与选定历史授权继续实施，T23 整体不关闭。

## 2026-10-03 T23 按需下载与认证缓存读取

共享核心新增显式下载准备、逐块续传、失败/远端不可用状态、公开媒体信息和 Rust 内认证读取。描述只从当前身份可见且认证成功的原消息获取，密钥不返回页面；原设备授权与当前资格共同约束远端下载。部分密文及其本机摘要持久化，重开继续原编号/描述；摘要只保护本机进度，全部分块通过完整摘要、MAC、长度与格式验证后才标记 Cached。缓存每次读取重新认证，损坏不返回明文；下载失败不会制造新消息、未读或 ACK。

取消、会话轮换和锁定拒绝迟到分块；隐藏与取消下载同一受保护事务，隐藏后信息、任务、下载、缓存读取均拒绝，不恢复卡片。签出或远端过期不删除已下载认证副本；未缓存或清理后远端过期明确不可用。下载遵守统一 256 MiB 逻辑限额，清理后只能凭原可见消息重新下载，不能转换成新发送。

## 2026-10-02 T23 持久媒体上传与收件校验

## 2026-10-02 T23 媒体签名协议与独立服务端对象基础

新增 v3 媒体描述、密文引用及单独签名绑定。名称、类型、时长和随机文件密钥只进入逐设备加密描述；公开引用只有密文大小/摘要，绑定原批次完整摘要。原文字批次、收据和 ACK 格式保持。支持对已准备原批次确定性重绑定，不生成新编号、盐或收件密文。共享验证限制 20 MiB 文件、11 MiB 语音密文前载荷和 60 秒声明时长，解密检查完整摘要、MAC、长度和媒体格式；服务端不验证实际录音时长。

## 协议、存储和兼容性

- PostgreSQL 新增迁移 4–6：附件对象/分块、联系人投递策略、回应事件。SQLite 在既有初始化中创建通知、加密整理数据、附件任务和回应表。不删除原消息和数据库。
- 附件在既有签名信封的加密正文中使用 `LiteSeal:2` 格式，外层信封及签名字段不变。Rust 解密出口剥离附件密钥，渲染进程只读文件信息。**试用双方客户端和服务端必须一起升级**，旧客户端不是附件兼容目标；新界面对未知附件版本显示占位。
- 文件使用每对象随机密钥和认证加密；名称、MIME、密钥仅在加密描述内。服务端对象绑定消息编号与收件身份，收件人下载需要已签名消息的持久 receipt。消息 ACK 与文件下载是两个状态。
- 默认对象期限 30 天，孤立对象 24 小时回收。`LITESEAL_ATTACHMENT_DAYS`（1–365）和 `LITESEAL_ATTACHMENT_ORPHAN_HOURS`（1–168）可调整。启动后及每小时清理，到期下载立即拒绝。每账号 512 MiB/2000 对象；本机 256 MiB。清缓存不删正文、链和待发任务。SQLite 空间可复用，不保证文件缩小；界面单独展示数据库和日志文件大小。
- 上传沿用同一对象/消息编号。取消任务不撤回已提交消息，过期暂存提示同任务重新上传。保存仅使用主进程系统对话框选定路径；认证前不写目标文件。图片预览在内存中拼接认证内容，不建立明文预览缓存。
- 搜索每批 100 条，最多保留 500 条结果摘要，显示总匹配/扫描/跳过数。匹配在本机内存中完成，无明文索引。上下文前后各 20 条；撤回/删除不再可搜，引用/转发快照沿用既有保留规则。
