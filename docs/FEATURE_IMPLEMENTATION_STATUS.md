## 协议、存储和兼容性

- PostgreSQL 新增迁移 4–6：附件对象/分块、联系人投递策略、回应事件。SQLite 在既有初始化中创建通知、加密整理数据、附件任务和回应表。不删除原消息和数据库。
- 附件在既有签名信封的加密正文中使用 `LiteSeal:2` 格式，外层信封及签名字段不变。Rust 解密出口剥离附件密钥，渲染进程只读文件信息。**试用双方客户端和服务端必须一起升级**，旧客户端不是附件兼容目标；新界面对未知附件版本显示占位。
- 文件使用每对象随机密钥和认证加密；名称、MIME、密钥仅在加密描述内。服务端对象绑定消息编号与收件身份，收件人下载需要已签名消息的持久 receipt。消息 ACK 与文件下载是两个状态。
- 默认对象期限 30 天，孤立对象 24 小时回收。`LITESEAL_ATTACHMENT_DAYS`（1–365）和 `LITESEAL_ATTACHMENT_ORPHAN_HOURS`（1–168）可调整。启动后及每小时清理，到期下载立即拒绝。每账号 512 MiB/2000 对象；本机 256 MiB。清缓存不删正文、链和待发任务。SQLite 空间可复用，不保证文件缩小；界面单独展示数据库和日志文件大小。
- 上传沿用同一对象/消息编号。取消任务不撤回已提交消息，过期暂存提示同任务重新上传。保存仅使用主进程系统对话框选定路径；认证前不写目标文件。图片预览在内存中拼接认证内容，不建立明文预览缓存。
- 搜索每批 100 条，最多保留 500 条结果摘要，显示总匹配/扫描/跳过数。匹配在本机内存中完成，无明文索引。上下文前后各 20 条；撤回/删除不再可搜，引用/转发快照沿用既有保留规则。
- 备注、列表、收藏编号和便笺使用单账号加密整理数据，首版总量 1 MiB。收藏不保存正文快照，每次按消息可见性读取；便笺不发服务端。
- 联系请求最多 100 个待处理身份。接受前不接收新消息密文，由发送方 outbox 保留原消息重试。拒绝/拉黑无正常通知/未读；拉黑前已存离线密文隔离保留以保护消息链，重新接受后恢复。解除拉黑只恢复待处理状态。已收消息不被擦除。撤回仍可补收，被拉黑者的新编辑正文停止投递。**既有联系人升级后需显式允许接收。**
- 回应使用独立签名域 `LiteSeal/reaction/v1`，覆盖目标、身份、设备、版本、密文。每用户维护自己的版本，清空也是事件。服务端不知道 emoji；撤回后的 UI 不显示回应。
- 应用锁可选，启用前先验证 Windows 账号密码，避免无可用密码的设备意外锁定。不支持 Hello PIN，不是全库加密。普通重启读取持久配置并先锁定；Windows 解锁不自动解开应用锁。主进程拦截锁定时的业务 IPC。未启用应用锁时 Windows 锁屏仍抑制通知。
