# 群协作（T21）

## 当前能力与边界

Windows 群界面已提供 @成员、群主单位置顶和实名单选投票。需要迁移 12 的服务端及新版客户端；旧文字 V1 格式保持不变，旧客户端不会取得协作流中的新内容。能力查询失败时不开放协作操作，普通文字仍使用原通道。

- @成员从输入框的 @ 或“提及成员”选择，绑定账号、设备及加入阶段，同一成员去重；目标变化须重新选择。不提供 @所有人。尚未发送的正文沿用加密文字草稿，选择的提及目标仅保留在当前面板，切换/重启后需重新选择；入队后目标和正文一起保存在加密任务中。
- 群主置顶一个已接受的消息，新置顶替换旧置顶；支持普通文字、提及与投票根消息。只有仍处于原授权加入阶段的当前成员取得目标编号密文。其他当前成员只验证不含目标编号的签名头，看到“不可用”占位。隐藏原消息不恢复正文；定位可继续读取旧历史页。群关闭后禁止修改。
- 成员可创建实名单选投票：题目 200 字符、2–10 个非空且去除首尾空白后不重复的选项，每项 100 字符。创建后内容不能编辑。
- 创建时成员且当前仍在原加入阶段者可投票、改票；每人一个当前选择，不提供弃票。发起人或群主可关闭，关闭不可撤销。离开成员已有票保留并标注已离开；重新加入不恢复旧资格。新成员不取得旧投票内容。

## 协议与存储

`LiteSeal/collaboration/v1` 签名绑定群/成员版本、操作人账号/设备/加入阶段、事件编号、对象编号、版本、前序哈希、操作及每收件密文的摘要。题目、选项文字、提及正文及目标列表逐成员认证加密。服务端可见实名投票人、随机选项编号、状态与路由元数据，不能读取题目/选项文字。不得描述为匿名投票或隐藏全部元数据。

置顶公开头只含目标编号哈希；服务端提交请求另外携带目标编号以核对原消息收据或协作根授权，不向无权限成员返回该编号。客户端重放置顶签名头验证版本链，收到的可解密内容必须与签名承诺一致。新成员可见这些无正文的置顶证明元数据，但没有旧目标密文。

独立 REST：`/groups/:id/collaboration` 提交/分页读取，`/ack` 确认，`/capabilities` 查询。现有群事务锁串行化成员变更与协作提交；会话/设备有效性、权限、收件集合、加入阶段和对象版本在事务中检查。重复事件只接受完全一致的签名头及密文承诺。文字与协作编号不能相互占用。

每群最多保留 10,000 个协作事件；每设备跨群待收最多 1,000 项/10 MiB，提交沿用群操作每分钟 40 次限制，单请求最多 512 KiB，单密文最多 8 KiB。ACK 标记送达并解除待收额度，保留已接受密文和签名记录供原授权阶段重放；这不是物理清理方案。拉黑/拒绝会阻止协作下载，客户端不推进游标，解除后重试。

SQLite 增量表保存签名日志、带作用域绑定的加密内容、原任务、加入阶段游标和 ACK。验签、认证解密、内容与版本验证及落库同事务成功后才 ACK。正文根消息接入已有历史/未读/隐藏表；投票变化和置顶不增加普通消息未读或通知。提及和新投票使用通用群通知，沿用静音/锁屏/前台抑制及去重。

提及入队与清除正文草稿同事务完成；响应丢失也保留原密文和编号，使用“重试协作任务”。明确 409 拒绝的任务保留为冲突，必须显式放弃后重新操作；不会自动重签。超过提交时间窗口或成员版本变化也可能要求此流程。

群数据统计计入协作载荷和待发/冲突任务；隐藏历史保留签名链、密文、ACK、任务及其他草稿。隐藏投票后仍验证后续状态，但不重新显示根消息。投票详情每次最多 100 条，跟随历史分页加载，避免返回整个群的正文。

## 桌面接口与验证入口

新增五个业务命令：`get_group_collaboration`、`sync_group_collaboration`、`submit_group_collaboration`、`retry_group_collaboration`、`discard_group_collaboration_conflict`。本机视图允许指定当前历史页的最多 100 个消息编号；提交仅接受类型化业务操作，不接受私钥或原始签名事件。所有入口继承主窗口来源、锁定及会话失效检查。

```powershell
npm test
npm run test:database
npm run test:groups:integration
npm run test:groups:ui
npm run build
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo check --locked -p liteseal-core --features ffi
```

数据库入口使用带标记的专用库，准备方式见[数据库验收](DATABASE_TESTING.md)。三进程测试使用真实 PostgreSQL/服务/Rust 客户端，并通过本机代理注入 ACK/响应丢失和重放；UI 使用真实 Chromium、模拟业务接口。两者不能替代真实双 Windows、通知中心/锁屏、长期多群性能或独立协议审查。实际结果记入[实现记录](FEATURE_IMPLEMENTATION_STATUS.md)及[执行计划](NEXT_IMPLEMENTATION_PLAN.md)。
