# Windows 基础文字群（T20）

## 接入状态

基础文字群已从桌面顶部“群聊”入口接通。当前最多 10 位成员，一人创建后先邀请其他成员，受邀者独立核实并签名接受后才能参与。源代码、同机隔离双进程及模拟界面回归已完成；专用 PostgreSQL、两台 Windows 和 3～10 个账号的实际场景没有执行，验收框保持未勾选。

可用入口包括：群列表/分页、创建、核实邀请、接受/拒绝、核实恢复原群、明确设备与指纹的联系人邀请、成员列表、群主改名/移除/关闭、普通成员退出、文字发送/原任务重试/未发送取消、加密草稿和历史分页、本机未读以及后台补收。

## 身份与权限

- 邀请目标必须为本机已核实联系人，未标记公钥变化，并保留公开加密及签名公钥。Rust 向注册设备接口取得实际设备，比较两组冻结公钥。页面展示账号、设备和两组指纹；确认后再次验证指纹，变化时拒绝。
- 接受或恢复群之前，创建者提示仅作候选资料。需要自己原身份或已核实群主联系人作为独立信任锚；Rust 校验签名创建链后才保存。未知群不会自动信任服务端自签根。
- 页面不能传入私钥、原始群签名信封、任意服务器地址或会话凭据。16 个新群业务入口均通过既有主窗口来源和锁定检查，异步结果还受锁定代数及当前会话检查保护。
- 群主才能邀请、改名、移除和关闭；普通成员只退出自己。关闭/退出/移除界面说明历史与后续投递边界，并要求确认。最终权限继续由共享签名验证及服务端事务判断，页面角色状态不作为授权依据。

## 会话、存储与后台

`desktop/src/commands/groups.rs` 为同一规范化服务器/账号/设备/公开身份保留一个 Rust 客户端。刷新令牌复用原客户端及存储范围；退出或改变凭据使旧能力失效，返回前检查会话，旧正文不回到新会话。本机草稿/历史/未读不等待后台网络锁。

草稿每次更改立即进入串行保存队列，合并等待中的新版本。保存失败保留页面文字、阻止切换/退出并提供重试；群封装任务与草稿清除在同一本机事务完成。发件失败展示待发送条目并保留原批次，重试不重新生成编号；取消使用服务端原子标记，已接受任务不伪装为取消。详细消息/历史边界见[群客户端核心](GROUP_CLIENT_CORE.md)。

主进程每 10 秒调用内部群处理，网络工作总时限 25 秒，每轮最多轮转 3 个本机群；邀请/远端群目录周期更新。本机 `received→seen` 只降低界面未读，页面聚焦、可见且未被对话框遮挡时标记，不发送群可见已读回执。锁定期间继续验证落库和 ACK，但不向渲染进程发正文或更新事件，解锁后重新读取本机数据。

群通知已有原生通用提示、点击进入群、30 秒节流和持久静音；通知不显示正文、群名或成员名，前台当前群与锁定期间不弹窗。静音不影响未读与后台收件。已发邀请管理、群数据单独统计/清理仍待接入；大量群、长期运行、真实托盘、休眠和网络恢复性能也尚未实测。T21 的提及、置顶及投票，以及群附件/回应/定时发送等不属于当前文字群交付。
