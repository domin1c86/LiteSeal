# 隐私安全与空间可控聊天软件计划书

# LiteSeal - 轻密

## 1. 项目概述

本项目计划开发一款面向 Windows 与 Android 用户的聊天软件，核心目标是解决现有即时通讯软件中常见的两个问题：

1. **隐私与数据安全不足**
2. **本地空间占用不可控、长期膨胀**

本软件不以成为 Telegram、微信或 QQ 的完整替代品为第一阶段目标，而是优先打造一个：

> 端到端加密、本地数据加密、媒体按需下载、空间占用透明可控的轻量级安全聊天工具。

---

## 2. 核心目标

### 2.1 隐私安全

软件需要确保：

* 服务器无法读取用户聊天内容
* 消息、图片、视频、文件均采用端到端加密
* 本地数据库加密存储
* 推送通知不暴露消息明文
* 日志、崩溃报告、缓存文件不包含敏感内容
* 用户可以控制消息与媒体的保存周期

### 2.2 空间可控

软件需要解决传统聊天软件长期占用大量空间的问题：

* 不默认自动下载大视频、大文件
* 图片原图、视频、文件按需下载
* 缩略图、缓存、临时文件设置容量上限
* 提供清晰的空间占用统计
* 提供一键清理能力
* 支持自动清理策略
* 清理后真正释放本地空间

---

## 7. 核心功能规划

## 7.1 端到端加密聊天

### 功能说明

用户之间发送的消息在发送端加密，在接收端解密。服务器只保存或转发密文，不能读取消息内容。

### 需要支持

* 文本消息端到端加密
* 消息签名
* 消息完整性校验
* 设备密钥管理
* 会话密钥管理
* 密钥轮换
* 本地解密展示

### 不建议

* 自研底层密码学协议
* 服务端保存明文
* 前端 JavaScript 直接处理核心密钥

---

## 7.2 本地加密数据库

### 功能说明

用户本地聊天数据需要加密存储，即使数据库文件被复制，也不能直接读取内容。

### 数据类型

```text
消息索引
消息正文
附件索引
缩略图缓存
用户设置
同步游标
设备信息
```

### 存储要求

* 消息正文加密
* 附件信息加密
* 敏感索引字段尽量加密或模糊化
* 日志不记录明文消息
* 崩溃报告不包含聊天数据

---

## 7.3 个人 Outbox 消息日志

### 功能说明

每个用户维护自己的已发送消息日志。每条消息由发送者签名，并带有序号和哈希信息。

### 作用

* 验证消息来源
* 防止消息被篡改
* 支持断点同步
* 支持未来扩展 P2P 或多设备同步
* 支持极限隐私模式

### 消息结构示例

```json
{
  "conversation_id": "...",
  "message_id": "...",
  "sender_id": "...",
  "sender_device_id": "...",
  "sender_seq": 1024,
  "prev_hash": "...",
  "timestamp": "...",
  "ciphertext": "...",
  "signature": "..."
}
```

---

## 7.4 媒体按需下载

### 功能说明

图片、视频、文件不默认完整下载到本地，而是按用户需要下载。

### 默认策略

```text
文字消息：默认加密保存
图片缩略图：默认保存
图片原图：按需下载
视频：按需下载
文件：按需下载
语音：可设置保存周期
```

### 目标

* 避免软件长期自动膨胀
* 避免无意义缓存
* 降低手机空间压力
* 让用户明确知道什么内容占用了空间

---

## 7.5 附件加密与分块传输

### 功能说明

图片、视频、文件在上传前先加密，再分块上传。

### 流程

```text
原始文件
→ 生成随机文件密钥
→ 加密文件
→ 文件分块
→ 计算每块 Hash
→ 上传加密块
→ 发送加密 Manifest
→ 接收方按需下载
→ 校验 Hash
→ 解密还原文件
```

### 可借鉴 qBittorrent 的部分

* 文件分块
* Hash 校验
* 断点续传
* 多源下载
* 去重存储
* 下载进度管理

### 不应照搬的部分

* 公开 Tracker
* 公开 Peer 列表
* 公开资源 Hash
* 明文文件名
* 长期公开做种

---

## 7.6 存储管理中心

### 功能说明

提供清晰可见的空间占用统计和清理能力。

### 示例展示

```text
当前总占用：1.2 GB

文字消息：32 MB
图片缩略图：180 MB
图片原图缓存：420 MB
视频缓存：300 MB
文件缓存：200 MB
临时文件：80 MB
数据库索引：20 MB
```

### 用户可操作项

* 清理图片原图缓存
* 清理视频缓存
* 清理文件缓存
* 清理临时文件
* 清理指定会话缓存
* 设置总缓存上限
* 设置自动清理周期
* 设置不同类型文件保存时间

---

## 7.7 自动缓存清理机制

### 功能说明

内置 Storage GC，即存储垃圾回收器。

### 清理对象

```text
过期媒体
未引用文件
失败下载残留
旧缩略图
临时文件
数据库碎片
超出容量限制的缓存
```

### 清理优先级

```text
1. 临时文件
2. 失败下载残留
3. 最久未访问的视频
4. 最久未访问的文件
5. 最久未访问的图片原图
6. 高清缩略图
7. 普通缩略图
8. 文字消息最后清理
```

### 保护规则

以下内容不应被自动清理：

* 用户手动收藏的内容
* 用户手动保存到本地的文件
* 用户标记为永久保存的会话内容

## 8. 隐私模式设计 (其实是对应了多种对话方式，标准是默认，高隐私可以对单一对话进行设置，极限模式是则相当于临时对话)

## 8.1 标准模式

适合普通用户。

```text
文字消息：本地加密保存
图片缩略图：保存
图片原图：按需下载
视频：按需下载
文件：按需下载
缓存：自动清理
```

优点：

* 体验好
* 空间占用低
* 适合默认启用

---

## 8.2 高隐私模式

适合重视安全的用户。

```text
文字消息：加密保存
对方消息：可设置过期
媒体：退出会话后可清理
通知：不显示联系人和内容
搜索：可关闭
截图提醒：可选
```

优点：

* 隐私更强
* 数据暴露面更小
* 适合敏感沟通场景

---

## 8.3 极限模式

适合极高隐私需求用户。

```text
只长期保存自己发送的消息
对方消息仅临时显示
关闭会话后删除对方消息
再次查看时重新同步
```

优点：

* 本地占用极低
* 隐私强

缺点：

* 离线时历史消息可能不完整
* 搜索困难
* 对方删除数据后无法恢复
* 群聊体验较差

### 产品建议

极限模式可以保留，但不建议作为默认模式。

## 17. 核心风险

### 17.1 Android 后台限制

Android 不适合承担长期 P2P 节点职责，因此第一版应依赖加密中继服务器，而不是完全 P2P。

### 17.2 密钥恢复问题

如果用户丢失设备或忘记密码，历史消息是否能恢复，需要提前设计。

可选方案：

```text
不提供恢复，安全性最高
提供用户自管恢复码
提供加密云备份
提供多设备恢复
```

### 17.3 元数据泄露

即使消息内容加密，服务器仍可能知道：

```text
谁在什么时候通信
消息大小
设备在线状态
IP 地址
推送触发时间
```

产品宣传时不能夸大为“绝对匿名”。

### 17.4 用户体验风险

如果默认启用极限隐私模式，可能导致：

```text
历史消息不完整
离线体验差
搜索困难
换机麻烦
```

因此建议默认使用标准模式，把极限模式作为高级选项。

## 20. 最终结论

本项目应围绕两个核心价值展开：

```text
隐私安全
空间可控
```

推荐继续保留：

```text
Tauri + Rust
端到端加密
个人 Outbox 日志
消息签名
加密中继服务器
附件分块
按需下载
缓存清理
存储管理中心
多种隐私模式
```

建议避免：

```text
默认只保存自己发送的消息
默认自动下载所有媒体
第一版做复杂群聊
第一版做完全 P2P
服务端保存明文
自研底层密码学协议
```

第一版最重要的目标不是功能多，而是把以下体验做到足够好：

```text
安全地发消息
安全地存消息
不乱占空间
用户知道空间用在哪里
用户能真正清理掉不想要的数据
```
