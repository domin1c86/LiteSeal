# 本机定时文字消息（T19）

## 使用范围

- 在会话中展开“本机定时文字”，编辑文字和本机计划时间，保存后可查看、修改或取消。任务保存独立文字副本，不含引用、转发、图片或文件，也不清空当前草稿。
- 文字最多 4096 UTF-8 字节；时间为至少 5 秒后、最多 30 天内。本机每账号/设备最多保留 100 个任务记录，可移除已提交记录，聊天消息继续保留。
- Electron 主进程每秒检查任务，应用运行且当前账号的中继连接有效时执行。收起到托盘或应用锁定后，预先安排的任务仍可执行；锁定期间不向渲染进程返回任务正文。完全退出后没有系统服务或服务器代发。

## 错过时间与中断

首次启动、重新联网、系统休眠或执行检查中断超过 30 秒后，已经到期的待发任务转为“已错过时间”，不会悄悄补发。全局提示给出需要处理的会话，用户可以立即发送、重新安排或取消。持续运行时任务串行执行，多个同一时刻的任务可能排队。

| 状态 | 含义与可用操作 |
| --- | --- |
| 等待计划时间 | 未分配链序号；可修改、取消或立即发送 |
| 已错过时间 / 准备失败 | 尚未封装到发件箱时，可修改、取消或立即发送 |
| 执行中断、发件箱结果待确认 | 已封装原消息时只允许重试同一消息；不能以取消任务冒充撤回 |
| 已提交到发件箱 | 不等于服务端接受或设备送达；查看聊天中的投递状态，移除任务记录不删除消息 |

单次准备/发送有 15 秒超时。网络写入前，现有发件机制持久保存消息编号、密文、签名和链位置；重试复用这些字节。执行中断后不自动猜测发送结果，用户处理仍使用原编号。服务端后续拒绝原消息时，任务会提示重试原消息。

## 数据和身份边界

SQLite 新增 `scheduled_messages`，按账号及原设备隔离。任务文字与收件身份公钥快照使用本机身份加密；联系人编号、时间、状态和错误元数据不作为全库加密的承诺。私钥留在 Rust，计划时间到达前没有聊天消息或链序号。

执行时再次核对本机联系人和服务端设备公钥与保存快照，身份变化会停止封装。只有用户重新核对联系人并修改任务后才使用新的身份快照。使用原有签名信封发送，不新增服务端协议或数据库迁移。

## 本轮验证与待验收

自动化覆盖：任务密文存储、账号/设备隔离、重复保存同一编号、到期前无链、错过时间、封装前/后中断、重启不重发、同一签名信封重试、联系人真实密钥变化阻断、IPC 管理及锁定时主进程执行但不返回正文。

Windows 真实时间到期、托盘、锁屏、休眠/唤醒、断网、时钟前后调整、不同任务同时到期、任务管理界面及双机收件尚未执行。验收清单 T19 保持未勾选，安装包事项不在本轮范围内。
