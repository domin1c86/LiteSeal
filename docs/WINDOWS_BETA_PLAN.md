# LiteSeal Windows 内测修复计划

制定日期：2026-09-10。基线提交：`4d2621e`。

本计划承接 [2026-09-06 审查报告](BETA_READINESS.md)。当时 79 项 Rust 测试、Clippy、前端构建和 Windows Release exe 构建通过；这些是历史基线，不代表下述工作已实现或安装验收已完成。

## 1. 目标、范围与默认规则

完成后交付可供 5–10 位熟人试用的 Windows 纯文本聊天版本：断网时安全保存消息，恢复网络后自动补发；重启、重投和回执丢失不造成静默丢消息；陌生发送者进入独立消息请求收件箱；能够构建、安装和部署。

用户已确认的范围：

- 使用全新账号开始内测，不要求迁移开发账号、v1 历史或旧待发消息。
- 每账号一台 Windows 设备，本轮关闭自助换机。
- 提供未签名内测安装包、版本号、SHA-256 和未签名说明。
- 离线点击发送后先加密保存，联网后自动发送，而非要求用户重新点击。
- 实现完整消息请求列表及接受、拒绝流程，不以待处理数量提示替代。

实施默认值：

- 首批支持 Windows 10/11 x64，服务端采用单实例 relay + Postgres 16 + Nginx。Android、多设备同步、附件、已发送消息撤回、SQLCipher 和代码签名不在本轮范围。
- 新 beta 使用独立本地数据目录 `liteseal/beta-v1/`，其下仍按服务器 origin 与 user id 隔离 profile。旧目录原样保留，禁止自动删除或导入。后续 beta 升级使用版本化迁移保留新目录的数据。
- 不支持离线首次注册或首次登录。已建立的有效本地会话可离线使用；显式退出后的启动必须保持退出状态。
- 未确认消息不再因固定 30 天 TTL 被静默删除。首批沿用每接收设备 1,000 条、10 MiB 服务端待处理配额；收件端本地待处理区使用同样上限。达到上限明确返回容量不足，并暂停新增接收或发送。
- 本轮保留去重和终态回执元数据，不做自动 TTL 清理。密文在收件端成功处理或明确拒绝后可删除；元数据不包含正文或密钥。结束内测后的清理策略另行制定。
- 默认“拒绝”界面显示为“拒绝并屏蔽”：处理当前请求并阻止该发送者后续请求；设置页提供解除屏蔽。解除后仅接受新的请求，不恢复已拒绝正文。
- 客户端和服务端作为同一 beta 版本配套升级。保留 v2 签名信封和既有验证边界；旧客户端不纳入本次兼容验收。

## 2. 必须保持的数据与接口约定

### 2.1 持久化与事务

| 存储 | 增加或调整的数据 | 不变量 |
| --- | --- | --- |
| 客户端 SQLite | 加密草稿、outbox、待处理 inbox、发送/接收链头、去重摘要、待发 ACK、消息请求与屏蔽状态 | 链头独立于聊天历史，清理聊天记录不能重置序号；隔离记录不能成为合法接收链头。 |
| 联系人 | 已核验的设备 ID、加密公钥、签名公钥及指纹快照 | 不能仅凭用户名或服务端新返回的密钥覆盖已信任身份。 |
| 服务端 Postgres | 扩展现有投递记录为可查询回执，记录发送者/接收者归属、信封摘要、序号及终态；队列增加稳定投递顺序 | 消息保存与 stored 回执同事务；ACK 处理、终态回执及密文清理同事务。 |

- 点击发送先保存受 Windows DPAPI 保护的正文，保护操作由 core 的平台存储接口完成；SQLite、localStorage、日志和测试快照不得保存明文草稿。网络加密仍只通过 shared 的 libsodium 包装完成。
- 本地消息记录、原始签名信封、序号及发送链头在同一 SQLite 事务中提交后，才允许发送网络请求。未完成信封构造的排队项不占用协议序号。
- 每条发送链以 `(conversation_id, sender_device_id)` 为键。每条链只允许一个尚未取得 stored/终态回执的信封在途；不同会话可独立推进。
- 同一消息的重发不得重新生成 ID、时间、nonce、签名或序号。服务端按消息 ID 与接收设备去重，同时校验发送者归属及完整信封摘要；相同 ID、不同内容返回冲突，不覆盖原记录。
- 对发送设备、会话和序号增加唯一性约束，阻止同一序号对应多个已接受消息。索引覆盖接收设备待投递队列、发送设备回执查询与联系人请求查询；用实际查询计划验证，避免全表轮询。
- SQLite/Postgres 都使用有版本号、事务化的前向迁移。迁移失败停止启动并保留原数据，不能吞掉 ALTER 错误后继续运行。

### 2.2 对外接口

| 边界 | 计划变更 |
| --- | --- |
| Tauri 发送命令 | `send_text` 在本地持久化成功时返回消息 ID 和 queued 状态，不再把网络连接成功作为提交成功条件；新增 `retry_message(message_id)`。 |
| Tauri 事件读取 | `poll_events` 增加连接状态、会话代次及请求列表变更。保留这一 UI 消费方式，网络接收、持久化和 ACK 改由 Rust 后台任务驱动，不依赖 React 轮询。 |
| Tauri 请求管理 | 新增请求列表/详情、接受、拒绝、屏蔽列表及解除屏蔽命令。所有操作按活动 profile 校验请求归属。 |
| WebSocket 错误 | 消息级错误附带 `message_id`、稳定错误码和是否可重试；认证/解析错误可不带消息 ID。 |
| WebSocket 回执 | 新增 `delivery_query`，每批最多 100 个 ID；复用投递状态响应，只返回当前认证发送设备所属消息。不存在或不属于当前设备均返回 unknown，避免探测其他账号。 |
| WebSocket ACK | `ack_v2` 增加处理结果 processed/rejected，缺省 processed；仍从认证连接确定接收设备。processed 对应 delivered，rejected 为独立终态，不能伪装成送达。 |

连接状态统一为 `connecting / online / reconnecting / offline / auth_required / logged_out`。消息状态统一为 `queued / sending / stored / delivered / retry_wait / failed / rejected`；delivered、rejected 不因迟到的 stored 更新而回退。

## 3. 实施阶段与完成条件

### M1：协议、存储和单设备边界

先实施第 2 节的接口、迁移、状态类型、事务和索引，并写协议往返及 repository 测试。

- 服务器在事务内锁定账号并检查设备归属，只允许原设备和原密钥重新登录；已有设备的账号不能通过省略 device_id 或设置 replace_device 创建新设备。
- 同时封闭直接注册新设备和原地轮换设备密钥的入口，防止绕过登录限制；设备列表恢复为正常只读查询。保留注销会话和安全撤销设备能力。
- UI 移除“确认替换后重试”流程，返回明确的 beta 单设备限制。遗失本地密钥时不自动接管账号，改由管理员为测试者创建新账号。
- 本地加好友/接受请求由 Rust 获取并校验远端设备信息，缓存用户核验的完整设备绑定；不能只信任前端传入的键值。
- 网络加密边界、退出登录状态、ACK 归属和现有 v2 签名测试必须继续通过。不要改动 UniFFI 对外接口，保持 Android crate/ffi 可编译，但不开展 Android 功能适配。

完成条件：并发设备注册不能突破一个设备；消息落盘失败不消耗序号；重复或冲突 ID 有确定结果；新 profile 迁移失败不会损坏旧开发数据。

### M2：后台连接管理和离线 outbox

- 每个活动 profile 只启动一个 Rust 连接管理任务，负责连接、认证、接收、刷新令牌、发送队列和取消。Tauri 负责安全持久化会话凭据，WebView 只接收展示状态。
- 连接超时 10 秒，普通 HTTP 请求超时 15 秒；WebSocket 每 20 秒发送心跳，10 秒未获回应判定断线。重连采用 1、2、4、8、16、30 秒封顶退避及 ±20% 抖动；手动重试立即唤醒。
- 网络故障持续重试；首次明确认证失败只尝试一次串行 refresh，新的凭据持久化成功后再重连。refresh 明确失效进入 auth_required，不无限刷新；网络失败仍进入退避。退出和账号切换取消全部旧任务，迟到响应按会话代次丢弃。
- 离线发送仅允许已核验联系人。已有设备缓存时也不立即投递：恢复连接后，先核对远端设备及密钥，再构造或重发信封；缓存缺失时保留加密 queued 项，等待联网解析。密钥变化暂停该会话，不自动改绑或重加密发送。
- 启动、重连时恢复 outbox，并先批量查询未终结消息的服务端状态；unknown 重发原信封，stored 等待处理回执，终态更新本地。在线时每 30 秒查询尚未终结的 stored 消息，弥补发送者错过实时回执的情况。
- 限流、队列满、网络和临时存储错误保持可重试；永久内容/身份错误显示 failed 并暂停所属链。已签名信封不支持编辑、取消或跳号，修复失败原因后重发原信封；尚未签名的排队项可取消。
- UI 仅在本地保存成功后清空输入；失败保留当前草稿。按 profile 和会话隔离草稿、列表及请求状态，切换账号取消旧读取；重发更新原消息，不追加第二条气泡。

完成条件：有效会话在网络恢复且服务可用后 60 秒内自动重连；重启后继续发送；任何持久化/发送边界上的中断都不丢正文、不重复分配序号。

### M3：统一投递、有序接收和可恢复回执

- 服务端所有消息先进入 Postgres 队列，再由当前接收设备的一条投递任务读取；在线发送只唤醒任务，不绕过数据库直接投递。实时和积压走同一条通道，保留连接代次检查与会话撤销校验。
- 每连接最多 128 条待 ACK 消息；ACK 后补满窗口。15 秒无 ACK 可重投原记录；写阻塞有超时，数据库中的未确认副本保留。轮询补偿丢失的唤醒通知，慢连接不产生无限内存队列。
- 客户端先检查身份和元数据，再按 ID/摘要去重。已成功处理且内容相同的副本只补 ACK；冲突内容隔离并记录独立事件，不覆盖合法历史。
- 有效签名但序号超前的消息进入持久化待补齐区，不 ACK、不提升链头；前序到达后连续处理。密钥未知、联系人未接受、密钥变化也进入待处理区，并在对应状态变化后自动重试。
- 本地正常消息插入、接收链头更新及待发 ACK 同事务完成；网络 ACK 发送失败不得撤销已保存消息或丢失后续接收事件。待发 ACK 在重连后继续发送。
- 已确认无效的载荷持久化隔离原因，发送 rejected ACK；拒绝不能显示 delivered。只有验证成立的连续消息可以推进合法链，禁止以隔离消息的最大序号充当链头。
- 历史展示使用数据库保存的 protocol_version、verification_state 和隔离状态，不再根据 local_state 字符串猜测真实性。普通历史清理不得删除链头、仍在队列中的正文、未发送 ACK 或去重证据。

完成条件：1,000 条积压与实时消息混发、断线重投、ACK 丢失、发送方离线收到的终态均可恢复；乱序等待和真正篡改在状态及测试中明确区分。

### M4：完整消息请求收件箱

- 增加独立“消息请求”入口、未处理数量、请求列表和详情，沿用现有 UI 风格，不进行整体视觉重设计。
- 请求按发送用户、设备和密钥指纹聚合，保存未接受密文。接受前只显示经认证接口取得的用户名、用户 ID、设备指纹、首末时间及条数，不解密或预览正文，也不标为已验证联系人。
- “接受”先展示指纹并要求用户明确核验；事务性创建已核验联系人绑定、更新请求状态，然后按 M3 顺序处理全部挂起消息。后续消息进入普通会话，不要求重启或再次发消息。
- “拒绝并屏蔽”持久化拒绝决定和待发 rejected ACK，清理请求正文并阻止后续请求；设置页可解除屏蔽。保留可验证的序列/摘要证据，解除后不能因删除正文重置链；无法建立连续证据时显示待补齐，禁止强行跳过校验。
- 默认最多 100 个未处理请求，同时受本地 1,000 条/10 MiB 待处理总配额限制；超限提示容量不足并停止确认新增载荷，不通过 ACK 丢掉尚未处理的数据。
- 列表在重启后恢复。接受、拒绝和解除屏蔽均须防重复提交；请求处理中的账号切换不能把结果写入另一账号。

完成条件：Alice 已添加并核验 Bob、Bob 未添加 Alice 时，Alice 的消息进入 Bob 请求箱；Bob 接受后历史自动出现，拒绝后不会显示送达；离线处理请求的决定在联网后可靠同步。

### M5：部署、邀请码和 Windows 安装包

- 修复 Dockerfile，复制 Cargo workspace 所需成员，使用 `cargo build --locked --release -p liteseal-server`；添加构建上下文排除规则，排除 target、node_modules、Git、环境凭据和本地数据。服务镜像以非 root 用户运行。
- 构建输入记录 Rust/Node/原生库版本及镜像 digest，保留 Cargo/npm 锁文件；在干净 Windows 环境重建 libsodium 链接链路，解决 CRT 冲突，提供调试符号或明确不生成符号，不能全局屏蔽链接警告。
- Compose 提供 Postgres、relay、Nginx 三个服务，Nginx upstream 与实际 service 名一致；仅代理公开端口，relay/Postgres 使用内部网络。证书与域名通过部署参数提供，生产配置不允许默认口令或通配 CORS。
- 提供本地 HTTPS/WSS 集成测试配置，使用专用测试 CA；不得关闭客户端证书验证。实现每天的 Postgres 备份脚本、7 份轮换及恢复到独立库的演练步骤；迁移前额外备份，回滚采用对应备份恢复，不直接执行破坏性降级 SQL。
- 增加仅供维护者在本机/服务器命令行使用的 `liteseal-admin invitations create/list/revoke`，不开放公网管理接口。默认批量 10 个、7 天有效、单次使用；数据库只存哈希，原码只写入操作者指定的受限文件，列表和日志不显示原码。
- 同步内测版本为 `0.2.0-beta.1`，生成 x64 NSIS 当前用户安装包。默认保留用户数据，升级保留 beta profile；卸载时删除程序，清除聊天数据必须是明确选择。保留自动更新为关闭状态。
- 发布目录包含安装包、SHA-256、commit/版本清单、未签名说明、安装/升级/卸载步骤、已知限制和脱敏反馈模板。不得要求测试者关闭系统安全软件。
- 增加不包含正文或凭据的诊断：连接状态及重试次数、队列数量与最旧等待时长、失败码、隔离计数、数据库就绪状态。内测期间以 readyz 失败、容量耗尽和持续投递失败作为维护者排查信号。

完成条件：能从干净环境构建并启动完整服务栈、备份后恢复；普通 Windows 用户可安装、启动、升级和卸载。部署参数、证书与主机由实际部署时提供；在用户批准前仅完成本地可审查产物，不推送、不部署、不发放邀请码或安装包。

### M6：验收与试用

执行第 4 节自动化与人工矩阵，并把版本、命令、结果及脱敏证据写入 TESTING_GUIDE/BETA_READINESS。

顺序固定为：完整自动化门禁 → 开发者两机验收 → 经批准邀请 2 人试用 24 小时 → 无阻塞问题后扩至 5–10 人并观察 72 小时。发现丢消息、越权投递、跨账号泄漏或未解决 P1，立即暂停扩量并回到修复和回归。

## 4. 测试矩阵与放行标准

| 层级 | 必测场景与断言 |
| --- | --- |
| 协议/存储 | 所有新增消息往返；ID 相同内容不同；重发信封逐字节不变；并发 enqueue；事务回滚；数据库磁盘写入失败；链头不随历史删除丢失；草稿文件/DB 中无测试正文的明文。 |
| 连接/会话 | 退避与超时使用可控时钟测试；断网、网络切换、睡眠唤醒、服务重启、token 过期、refresh 失败及响应丢失；退出与切换账号取消全部旧任务，不回写旧 UI。 |
| 故障恢复 | 在保存前后、发送前后、stored 回执前后、接收落盘前后、ACK 发出前后注入中断；恢复后核对消息 ID 集合、正文、序列与状态，不能只比较条数。 |
| 真实 Postgres/WebSocket | 1,000 条积压排空、积压与实时混发、慢连接、重复包、乱序缺号、伪造 ACK、身份不匹配、条数和字节配额边界、发送者离线期间的 delivered/rejected 回执补查。积压夹具可预置合法连续信封，发送限流单独按真实阈值测试。 |
| 请求收件箱 | 未知发送者、指纹核验、接受后补处理、拒绝与屏蔽、解除屏蔽、离线决定、容量上限、密钥变化、重启恢复、处理请求时切换账号。 |
| UI | 用固定 IPC 夹具覆盖状态展示、保存失败保留输入、重发不新增气泡、迟到回执不回退、请求列表交互。夹具必须与 Rust 序列化契约一致；浏览器夹具不能替代真实 Tauri 验收。 |
| 两台 Windows | 全新注册、同设备再登录、禁止新设备接管、双向聊天、离线发送、双方未互加联系人、重启、账号切换、logout/logout-all、安装升级卸载；Windows 10/11 各至少覆盖一台。 |
| 部署/恢复 | 镜像构建、健康/就绪检查、正确和错误证书、HTTP→HTTPS、WebSocket 代理、服务重启、Postgres 备份恢复、单次邀请码并发消费、未签名安装包完整性校验。 |

自动化门禁必须包含：格式检查、workspace Clippy、所有 Rust 测试及显式 Postgres 用例、新增 UI 测试、前端构建、脚本自身回归、在线依赖审计和实际 NSIS 构建。保留已有 SECURITY.md 例外的复查期限，不新增忽略项来掩盖失败。

正常登录且服务可达的情况下，网络恢复 60 秒内进入 online；小批本地/局域网正常消息在 3 秒内显示给在线收件人。负载和网络条件随结果记录。正确性放行标准是消息集合与顺序一致、无未解释丢失、无重复展示、无未经允许的投递、无跨账号数据残留，并且所有必测项有本次证据。

没有第二台 Windows、外部部署授权或持续观察时间时，明确标记对应验收未完成，不能用单机模拟或一次绿色构建替代。

## 5. 执行与交付约定

- 实施顺序为 M1 → M2 → M3 → M4 → M5 → M6；每阶段完成后验证再进入下一阶段。每个独立完成的修改按仓库格式创建本地提交，不把全部工作压成一个提交。
- 修复前先将对应源码推断变成可失败的回归用例；保留本轮已修复的路由、消息持久化、撤销、退出恢复、迁移并发及门禁测试。
- 范围新增完整请求箱，旧审查中“只提示待处理、要求双方先添加”的建议不再作为最终产品方案。执行中同步更新审查报告，但不得把计划中的项目提前勾选为完成。
- 保留用户现有修改和两个未跟踪预览文件；不修改与本计划无关的设计稿。无需为纯文档工作重新运行应用构建。
- 实施结束交付：可复核的本地提交、完整测试记录、安装包与校验清单、可部署配置、邀请码维护工具、备份恢复指南、两机验收记录及未完成外部条件。准备完成不等于已批准对外发布。
