# T26 消失消息技术验证

## 2026-10-03 原生可运行阶段

新增 `shared::disappearing_message::Packet` 和 `core::trusted_devices::messages::expiry_trial::Trial`。这是使用隔离数据库的技术验证，还没有生产中继、会话期限开关或桌面/手机发送入口。T26 不勾选。

新包采用独立协议标记，将原始 v3 全批次摘要、原消息编号、原签名发送时间和到期时间绑定到原发送设备的 Ed25519 签名；原批次仍保留完整身份、受众、目录、链顺序与逐设备密文。期限仅在新包创建时指定，范围为 1 秒至 7 天（验证用边界，不是正式产品选项）。旧 Batch 读取器拒绝整个新包；不把期限作为可剥离的界面 JSON 或未签名 `expire_at` 列，不修改旧消息的期限。

目标先核对原目录、原批次和期限签名，再以本机独立密钥保护期限记录，复用原 v3 接收、完整性和持久 ACK 规则。新期限记录与单一观察时间高水位都进入已有原生外部见证。读取时使用最高已观察时间；一旦到期，该标记永久保留，重开、旧时间、重复投递或恢复旧 SQLite 不能重新展示。

正文、搜索、通知资格、正文导出及附件解密都调用同一个原生门禁。到期只改变可见性，不删除原批次、密文、签名、链头、去重和 ACK。附件缓存仍保留为密文，门禁先于解密；不声称收回已另存为文件、截图、复制或阻止物理取证。当前普通便携备份拒绝含验证期限记录的档案，避免遗漏期限后恢复正文；正式便携期限格式仍待接。

`target/test-results/disappearing-native-trial-final.log` 实际 3/3 通过：

- 签名期限篡改/旧解码器拒绝，到期前后正文、搜索、通知及导出一致；重开/时钟回退/重复补收不复活，原签名包及 ACK 保持，后续消息链可继续。
- 已过期消息离线到达直接不可见；恢复旧 SQLite 被独立高水位拒绝，原链/ACK 保留。
- 合成附件到期前正确读取、篡改拒绝，到期及回退后不可读取，原证明仍保留。

早期私有类型别名、夹具消息编号/发件状态 API 不匹配导致的编译或夹具失败均留在原日志；最终通过是修正夹具后的真实原生执行。没有真实用户密钥、聊天或文件输入。

接续：明确统一升级/能力准入、生产原任务封装与中继、仅新消息的期限设置、前台已显示正文定时退役及系统通知退役、正式便携/授权历史保留期限。发送时间来自原作者签名，不是可信全球时钟；正式路径需限定服务端接受时间与发送时钟偏差。外部见证阻止数据库/应用文件回滚，不承诺阻止管理员恢复整个系统安全存储。Android Keystore 高水位仍需模拟器/真实手机断电与回滚验证。
